# 本地开发环境启动

## 1. 定位

本工具负责启动 Frontend Real Mode 与 Electron，并明确区分 Local Backend Dev 和 VPS Backend Dev。它不是产品功能或 Worker 能力。

## 2. 首次配置

- `C:\Users\<user>\.ssh\config` 已存在 `control-center-dev` 与 PostgreSQL LocalForward。
- `backend/.env` 已配置专用 `control_center_dev` URL 与 `BACKEND_ENCRYPTION_KEY`。
- Backend `.venv`、根 pnpm 依赖已安装。

真实数据库密码、完整 URL、SSH Key 与加密密钥不得写入脚本、文档或 Git。

## 3. Local Backend Dev

```text
Electron → Frontend → 本地 FastAPI → SSH Tunnel → VPS PostgreSQL
```

用于 Backend 开发，默认模式：

```powershell
pnpm dev:up -- local
pnpm dev:status
pnpm dev:down
```

`dev:up` 不带参数也等价于 `local`。它按顺序检查或启动 SSH Tunnel、验证 PostgreSQL、启动并等待本地 Backend `/health`、启动 Vite Real Mode、最后启动 Electron。

## 4. VPS Backend Dev

```text
Electron → Frontend → VPS FastAPI HTTPS → VPS PostgreSQL
```

用于多 Worker与真实集成测试。先在当前终端通过私有环境配置注入正式 HTTPS 地址，再启动：

```powershell
$env:CONTROL_CENTER_REMOTE_API_URL = 'https://由负责人提供的真实域名'
pnpm dev:up -- remote
```

也可双击 `启动中控台-远程Backend.cmd`，但环境变量仍必须预先存在。Remote 模式只把该地址作为 Vite 开发代理目标，不修改源码和 `.env.real`，也不启动本地 Backend 或数据库 SSH Tunnel。脚本拒绝非 HTTPS 地址；当前 VPS 尚无域名/TLS 时，此模式按安全规则保持不可用。

切换模式前必须先执行 `pnpm dev:down`，避免复用指向旧 API Target 的 Vite 进程。已有健康进程会复用；端口被非目标服务占用时立即失败，不重复启动。

`dev:status` 输出组件状态、Real API 模式、Dev 模式和 API Target，不输出数据库账号密码或 Token。API Target 仅允许非敏感 HTTPS 服务地址。

`dev:down` 只停止本工具写入 `.dev-runtime` 的精确根 PID 及其子进程树；手工启动或其他项目的 Python、Node、SSH 进程不会被终止。

## 5. 运行状态目录

`.dev-runtime/` 被 Git 忽略，只保存本次工具启动的 PID 身份与非敏感日志。PID 同时校验进程启动时间，避免 PID 重用后误杀其他进程。

## 6. 故障处理

- PostgreSQL 未连接：检查 SSH Config、密钥和 VPS PostgreSQL 开发容器，不在本脚本中远程重启容器。
- Backend 未健康：查看 `.dev-runtime/backend.err.log`。
- Frontend 端口占用：先确认 `5173` 是否为本项目 real-mode Vite。
- Electron 未启动：查看 `.dev-runtime/electron.err.log`。
