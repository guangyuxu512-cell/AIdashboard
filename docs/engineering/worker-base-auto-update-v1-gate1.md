# Worker 底座自动更新：Gate 1 交接

- 基线：Green dev `f3bd537ea5d52208e613203095bec527ad0e03d2`。无 Migration，无业务数据库写入。
- 使用现有设备认证和离线 Ed25519 信任锚，中控只分发签名清单及内容寻址的包；Worker 不访问 GitHub，也不持有 GitHub 凭据。能力包与底座各自保留版本清单。
- 有预检运行时，发现受信任的新版本后停止领取新任务，等待在途任务、结果和事件交付；下载、校验并在独立目录启动新版，认证心跳通过前不能领取任务。失败恢复旧版并拒绝重复切换；发布方可递增清单序号安排复验。设备身份和本机 RPA 资料不由更新器修改。
- Worker 在原启动入口运行时校验已启用的新版本；旧版和用户配置独立保留。现存 0.5.5 没有底座自更新入口，需一次切换到支持自动更新的版本，不需要重新绑定设备或重新登录店铺。

## 验证

- Worker 全量 pytest 通过；底座更新 API 与既有能力包 API 定向测试通过。HTTP API 测试使用身份依赖替身。
- 使用受信任正式公钥构建的 Windows 0.5.8 包通过包内容、版本与信任锚离线自检；未将私钥或设备凭据打包。
- 两个实际 Windows 打包程序在隔离目录、模拟中控与测试签名下执行 0.5.8 → 0.5.9：任务完成后才下载切换；模拟新版心跳失败时回到旧版；原启动入口可启动已启用版本；启动和停止控制正常。另用 Windows DPAPI 合成设备配置验证跨版本保留、正常启动。两种测试均检查本机店铺资料哨兵不变。
- 验证不接触真实平台、生产设备或生产数据。尚需 Integration Gate 2、精确 CI 和正式发布；上述模拟不等于生产设备已自动升级，也未实测当前公开仓库被改为私有后的 GitHub 服务。
