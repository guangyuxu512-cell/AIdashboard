# 商品属性按单位约束契约

- 已在正式设备只读观察类目 `1000009182` 属性 `2988`：属性自身非必填，度量模块 `432` 的值必填；平台对单位 `6`、`7`、`10` 返回各自上下限，单位 `242` 未返回对应规则。模块必填不改变属性本身的必填状态，缺失单位的行为不作推断。
- `validate_rule.unit_rules` 为 `null` 或空数组时原样保留；旧能力的未知哨兵 `[{"present":true}]` 继续被接受。只有完整、无重复的 `{unit_id, min, max}` 数组可透传：`unit_id` 为正整数，上下限为有限数值或 `null`，非空上下限满足 `min <= max`。任何未知键、类型、缺失字段、重复或无效范围使整组降为旧未知哨兵；通过中控回传时中控拒绝不符合契约的结果，直达商品库时须由商品库按同一契约验证。不得据未列出的单位或 `null` 推导平台约束。
- `unit_linkage` 的非空内容仍为未知标志；`extra.unit_rule_type` 及其他未经确认的元数据不透传。商品属性填写值、Cookie 和未知对象不进入结果。
- `input.require_schema_unit_rules` 是可选严格布尔值、默认 `false`，仅 `operation=schema` 可设为 `true`。显式启用时中控仅分配 `douyin.category_schema >= 2.0.3`，并在签名时重新核验；无兼容在线设备返回既有 `PRECHECK_UNAVAILABLE`。不启用时保持原有版本门槛和分配行为，2.0.2 仍返回未知哨兵。2.0.3 仅保证保留受支持的结构，不保证平台为每个单位返回约束。
- 商品库须先兼容新旧结构，将旧属性规则缓存与新版本区分；未识别结构或单位没有对应规则时保持未知。既有进行中的同商品、同 revision 请求不能追加该标记：输入哈希变化会按原契约返回 409，新的请求修订再启用该选项。
- 发布顺序：先部署中控兼容代码，再签名发布 2.0.3 能力包并确认设备实际加载，最后由商品库选择启用标记与新缓存。分阶段上线期间不得把代码或签名包准备完成当成设备已升级；不更改 Worker 底座、并发、店铺会话或数据库。
