# 核心领域模型

第一阶段长期稳定实体：
- User
- Shop
- Device
- Task
- Skill

后续按需求增加：
- Credential
- Session
- Workflow
- Trigger
- Order
- Product
- Finance
- AIAnalysis

所有关系通过稳定 ID 建立。

明确可能是多对多的关系，不要写死成单字段。
例如 Shop ↔ Device 推荐 `shop_device_binding`，支持 PRIMARY、BACKUP、enabled。

## Backend Core Domain V1

阶段 2A 正式建立 `User`、`Shop`、`Device` 与关系实体 `ShopDeviceBinding`。`Shop.owner_user_id` 可选关联负责人；Shop 与 Device 只通过关系实体关联，不在 Shop 上保存单一 `device_id`。一个 Shop 最多只能存在一个启用的 PRIMARY 绑定，BACKUP 可按关系独立管理。
