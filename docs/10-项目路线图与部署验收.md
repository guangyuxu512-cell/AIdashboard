## 3. 数据库创建口径

可以在同一服务器、同一 PostgreSQL 实例创建独立数据库，不必为每个环境另买服务器。数据库隔离不等于计算资源隔离。

- Feature：由 Integrator 分配并创建空 Feature DB，应用角色保持最小权限；Feature 连接已分配库执行 `alembic upgrade head`。
- Integration：`control_center_integration`。
- Main smoke：`control_center_dev`。
- Production：独立生产库，不复用以上测试库。

空库仅是起点；迁移后还需按正式初始化入口准备管理员、团队和所需配置，不能直接假设新库已有原来的账号/权限/模型。
创建/删除责任、Migration Slot 和操作步骤以 `engineering/03-数据库与Migration协作规范.md` 为准。本轮未创建任何数据库。

## 4. AI 图片存储证据与实施边界

代码依据：

- `backend/app/modules/assets/storage.py`：`AssetStorage` 协议及 `LocalAssetStorage` 实现。
- `backend/app/modules/assets/service.py`：未注入 storage 时默认使用 `LocalAssetStorage`。
- `backend/.env.example`：`BACKEND_ASSET_STORAGE_DIR=data/assets`。
- `backend/app/modules/ai_workbench/generation_service.py`：生成图片以 `AI_GENERATED` 来源进入既有 Asset 流程。

因此当前是“已实现图片持久化到后端文件目录”，不能表述为“尚无图片存储”，也不能表述为“已接入存储桶”。
后续必须复用现有 Asset 的所有权、权限与内容访问契约，不为 AI 再建一套文件表和存储业务层。
部署中的真实目录、持久卷、备份和是否存在未推送的对象存储实现，需在对应环境核实。

## 5. 系统设置只显示飞书的排查

`frontend/src/features/system-settings/ui/SettingsSideNav.vue` 在本轮核验的 main 与 dev 内容相同：

| 导航 | 显示条件 |
|---|---|
| 用户与权限 | auth.isAccessAdministrator |
| 操作日志 | auth.isAccessAdministrator |
| AI 模型管理 | auth.isAccessAdministrator |
| 通知配置 | allowedModuleCodes 包含 settings |

`frontend/src/stores/auth.ts` 从当前模块权限响应读取 `isAccessAdministrator`；切换团队会刷新权限。
拥有店铺接入能力不能据此推定具备权限管理员身份。

排查顺序：

1. 核对当前登录用户和所选团队，以及权限接口实际响应；不要只看本地数据库中某个名称类似“管理员”的字段。
2. 核对实际启动前端的路径、构建提交、端口及后端目标；如果连设置侧栏也不存在，重点核对旧包/旧进程。
3. 核对该后端所连数据库是否为预期环境，尤其新空库初始化后的用户、团队和权限。
4. 定位后通过正式权限或部署流程修正，不删除前端判断或绕过后端授权。

当前尚未取得用户运行实例的响应和进程证据，不能将权限原因或旧版本原因判定为已确认根因。
