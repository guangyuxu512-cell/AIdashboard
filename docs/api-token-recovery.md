# 可再次查看的 API Token

现有 Token 默认继续沿用只保存摘要的随机生成方式。统一管理页面在创建时传 `recoverable: true`，服务使用独立的 `BACKEND_API_TOKEN_RECOVERY_KEY` 与新 Token 的随机 ID 派生原文，并仍只将摘要写入原有表。没有配置足够长度的密钥时，只有可恢复创建和查看返回 503，既有签发、登录和 Token 调用不受影响。

生产密钥应独立随机生成并保存在现有受保护部署配置中，跨重启和版本升级保持不变，并进行安全备份。不得写入 Git、CI 输出或客户端；不得用示例值。密钥丢失或更换不会改变原有 Token 的认证结果，但无法再恢复用旧密钥派生的原文。历史随机 Token 的原文不能从摘要反推，查看返回 409，不会被重置。

`POST /api/v1/api-tokens/{id}/reveal` 只接受原有超级管理员人员会话，不接受 API Token；成功写入现有管理审计，响应不缓存。不存在或已撤销的 Token 不返回原文。

统一管理页面是独立仓库的静态产物，生产路径为 `/token-admin/`。只允许商品库令牌及分组查询和采集插件浏览器令牌管理路径经受限代理，保留各服务的 Bearer 校验。TLS 上游证书验证必须启用；生产前端使用宿主机网络，发布时须确认本机 systemd DNS 监听 `127.0.0.53` 并可解析商品库域名。原有 `/token-manager/` 暂不移除，直到新页面完成真实验收。
