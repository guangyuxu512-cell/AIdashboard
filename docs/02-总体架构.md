# 总体架构

```text
                    电商 AI 中控台
                         │
          ┌──────────────┴──────────────┐
          │                             │
     Server Modules                 Automation
          │                             │
     FastAPI / 服务端                  Task
          │                             ↓
          │                           Worker
          │                        ┌────┼────────┐
          │                        ↓    ↓        ↓
          │                       RPA  Python  Browser（未来）
          │
   ┌──────┼──────────────────────┐
   ↓      ↓        ↓             ↓
 AI作图  财务     数据分析      订单/商品
```

## Route A：SERVER

```text
Frontend → FastAPI Backend → Server Module / Service / Job
                              ↓
                 PostgreSQL / AI Provider / Platform Connector
```

这是不依赖具体电脑环境的默认路线，不经过 Worker。

## Route B：WORKER

```text
Frontend / Trigger → Backend Task → Worker → Executor → 本地能力
```

只用于依赖具体设备环境的自动化 Action。当前 Executor 为 PythonExecutor 与
RPAExecutor；BrowserExecutor 尚未实现。

设计目标：
- Frontend 可先 Mock，后续切真实 API。
- Electron 和 Worker 解耦。
- Backend 为模块化单体。
- PostgreSQL 是业务事实来源。
- Redis 是缓存/通知/协调能力，不替代事实库。
- RPA 是 Skill 执行能力，不承担任务调度。
- Worker 不是全局执行入口；执行目标按具体 Action 选择 `SERVER` 或 `WORKER`。
- Skill 是稳定能力标识，Executor / Provider 是设备侧实现，两者不得绑定为同一概念。

## 模块化单体与数据库演进

Backend 保持 FastAPI modular monolith + 单 PostgreSQL。新增业务模块拥有自己的 router、
schemas、service、repository/model（如需要）和 tests，跨模块通过明确 Service/Contract
与稳定 ID 调用；不引入动态插件加载、Module 数据库或 Runtime Module Loader。

PostgreSQL 表数量增加不是架构问题。业务实体正常建表，模块拥有自己的表，跨模块通过
明确 ID 关联，结构变更统一使用 Alembic。变化频繁的自动化配置允许合理 JSONB，但禁止
万能 `business_data` 表、所有功能塞进一个 JSONB、因担心表多而提前拆库。Worker 永不
直接连接 PostgreSQL；Redis、MongoDB、Elastic 均不得替代当前业务事实库。

## Automation Config 边界

未来 `AutomationConfig` 最小语义为 `skill_id`、`platform`、`version`、
`config_payload`（JSONB）与 `enabled`。Task/Run 必须能知道所使用的配置版本，Worker 通过
Backend 正式契约获取配置。本阶段没有真实云端元素配置需求，不建立表、CRUD API 或页面。

## Integration 边界

外部协作适配器放在 `backend/app/integrations/`。未来飞书配置编辑链路必须是
`Feishu → Adapter → Backend → PostgreSQL → Worker`，不得让飞书多维表格成为业务数据库。
