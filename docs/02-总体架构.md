# 总体架构

```text
                    电商 AI 中控台
                         │
          ┌──────────────┴──────────────┐
          │                             │
     Server Modules                 Automation
          │                             │
     FastAPI / 服务端                  Task
          │                             ↓
          │                           Worker
          │                        ┌────┼────────┐
          │                        ↓    ↓        ↓
          │                       RPA  Python  Browser（未来）
          │
   ┌──────┼──────────────────────┐
   ↓      ↓        ↓             ↓
 AI作图  财务     数据分析      订单/商品
```

## Route A：SERVER

```text
Frontend → FastAPI Backend → Server Module / Service / Job
                              ↓
                 PostgreSQL / AI Provider / Platform Connector
```

这是不依赖具体电脑环境的默认路线，不经过 Worker。

## Route B：WORKER

```text
Frontend / Trigger → Backend Task → Worker → Executor → 本地能力
```

只用于依赖具体设备环境的自动化 Action。当前 Executor 为 PythonExecutor 与
RPAExecutor；BrowserExecutor 尚未实现。

设计目标：
- Frontend 可先 Mock，后续切真实 API。
- Electron 和 Worker 解耦。
- Backend 为模块化单体。
- PostgreSQL 是业务事实来源。
- Redis 是缓存/通知/协调能力，不替代事实库。
- RPA 是 Skill 执行能力，不承担任务调度。
- Worker 不是全局执行入口；执行目标按具体 Action 选择 `SERVER` 或 `WORKER`。
- Skill 是稳定能力标识，Executor / Provider 是设备侧实现，两者不得绑定为同一概念。
