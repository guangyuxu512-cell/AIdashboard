# 抖店商家后台入口

商品库使用中控授权店铺查询抖店类目时，HuanYu 的罗盘身份验证可用，但商品接口返回 `10008`。对同一已核验店铺，使用相同中控状态与同一请求分别从电脑和 NAS 发送，均返回该错误；与商品库正式接口结果一致。同店成功浏览器状态仅在内存中补足一项商家后台认证信息后，类目查询成功。以上证据不证明平台何时改变要求，也不证明历史版本为何能通过。

已有抖店从中控点击“登录”后，罗盘身份仍按原流程自动同步；若同一次登录已经建立可用商家状态，不要求再次登录。已有店铺同步成功后窗口保留、租约释放；新增固定商家后台入口不接收外部 URL，也不因普通浏览反复保存。

当确需补齐商家状态时，用户在保留窗口主动打开商家后台并完成平台要求，随后关闭窗口、再次点击同一店铺“登录”；系统自动同步并验证，不需另点保存。菜单打开或登录页面出现都不代表商家状态已经同步。入口使用本机非敏感的一次性验证标记：点击前持久化，服务端确认该次快照同店并保存后才按原标记清除；失败、取消或标记被后续操作更新时保留。未使用该入口的普通罗盘同步不增加商家检查；若旧映射让多店共用同一 Profile，相关店铺共享待验证保护，避免跨店覆盖。

主动商家同步复用既有罗盘验证；无会话更新合并时只追加一次商家身份请求，有更新合并时需针对实际待保存快照重新核对罗盘和商家。明确错店、未确认或请求失败均保留原 Session；不会把 10008 等同未登录。旧 Profile 尚未完成商家同步时，商品库用途出口也会对当前快照验证，而不是假定旧状态已同店。

商品库的缓存命中只读授权店铺的 Session 版本元数据，不取得 Session、不请求平台。真实 merchant Session 读取需分别验证当前罗盘 ID、商家 ID 和目标店 ID，之后复核授权与原快照；两次平台请求共享 4 秒预算且不自动重试。冷类目并发活查可能并行重复验证，本候选不加入成功结果缓存或 single-flight；普通业务响应的 Set-Cookie 也可能递增 Session 版本并使缓存失效，并非只有手动登录才会失效。通用 V1 Session 出口保持原行为，不能宣称它已隔离商家状态。
