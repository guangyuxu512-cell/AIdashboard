# Mobile 设计系统

## 定位与唯一入口

Mobile 拥有独立的手机端视觉语言，不是 Desktop Frontend 的缩小版或主题镜像。视觉方向固定为：
克制、精致、清晰、轻量、偏原生 App；通过柔和 Surface、弱边框、有限阴影和清楚的信息层级
提高扫读效率，不使用霓虹、Glow、重毛玻璃、大面积渐变或 PC Dashboard 式装饰。

`mobile/src/shared/styles/tokens.css` 是 Mobile Design Token 唯一权威来源。颜色字面量只能出现在
该文件；Page、Feature、Entity、Shared UI 与 Vant 适配只能消费语义 Token。正式传递链路为：

```text
Light / Dark resolved theme
↓
Mobile Semantic Token
↓
vant-theme.css / Shared UI
↓
Feature / Page presentation
```

`mobile/src/shared/styles/theme.css` 聚合 Vant、Token、Vant Mapping 与全局基线；
`mobile/src/app/styles/index.css` 是应用唯一全局样式装配入口。禁止 Page Theme、Feature Dark CSS、
Device/Task 私有 Token，以及业务组件散落 `--van-*` 覆盖。

## Desktop / Mobile 完全解耦

- Desktop 与 Mobile 只共享品牌语义、状态语义、Token 命名思想和基础设计原则。
- 两端各自维护独立 Token 文件，不互相 Import，也不引用对方 Theme Variable。
- 两端各自维护独立的 Light、Dark、System 解析和值。
- 调整 Mobile 主题不得要求修改 PC 页面；调整 PC 主题不得影响 Mobile。
- Brand 语义可以一致，但实际颜色值不要求相等。
- Surface、Background、Border、Typography、Spacing、Radius、Shadow 与 Touch 尺寸均按终端独立设计。
- Mobile Header、Bottom Navigation 与 Card 质感不复制 Desktop Topbar、Sidebar、Table 或 Drawer。

## Mobile UI Development Stages（移动端 UI 开发阶段）

Mobile 核心 UI 按以下顺序定型，前一阶段未经人工验收不得提前开展后续阶段的广泛润色：
本文结构术语统一使用 Toolbar（工具行）、Meta（辅助信息）、Primary Selector（主选择器）、
Filter Action（筛选操作）、Visual Size（视觉尺寸）与 Touch Target（触控热区）。

1. Layout / Component Structure（布局 / 组件结构）
2. Dimensions / Spacing / Typography（尺寸 / 间距 / 字体排版）
3. Color / Surface / Radius / Shadow / Theme（颜色 / 表面 / 圆角 / 阴影 / 主题）
4. Interaction / Press / Motion / Touch（交互 / 按压 / 动效 / 触控）
5. Loading / Empty / Error / Toast / Dialog（加载 / 空态 / 错误 / 轻提示 / 对话框）
6. Business Interaction Contract（业务交互契约）

Stage（阶段）1 的组件计划固定为：Step（步骤）1A `MobileDetailHeader`、Step 1B
`MobileGlobalHeader`、Step 1C `MobileBottomNavigation`、Step 1D `MobileSummaryStrip`、Step 1E
`MobileListToolbar`、Step 1F Device Card / Task Card Anatomy、Step 1G `DeviceRuntimeSummary`、Step 1H
`CapabilityPanel`。Step 1A～1H 均已完成人工验收并冻结；Selected / Press / Motion、最终颜色、最终图标及
尺寸排版细调仍留给 Stage 2～4。

Status（状态）: Completed / Frozen（已完成 / 已冻结）

Stage 1 已冻结组件：

- `MobileDetailHeader`
- `MobileGlobalHeader`
- `MobileBottomNavigation`
- `MobileSummaryStrip`
- `MobileListToolbar`
- `DeviceCard`
- `TaskCard`
- `DeviceRuntimeSummary`
- `CapabilityPanel`

后续 Stage 2～6 只能在不改变上述组件 Anatomy（结构）、Hierarchy（层级）、Navigation Contract

Unfreeze（解冻）并重新确认，禁止在尺寸、主题、交互、状态或业务阶段顺手修改。

Stage 2 的真实参数位置、当前值与组件影响统一见

不改变本节冻结契约。

### MobileDetailHeader

Status（状态）: Frozen（已冻结）

Purpose（用途）: 普通 Mobile 详情页面统一顶部导航

Anatomy（结构）: Back Action（返回操作） + Centered Title（居中标题） + Reserved Right Action
Area（预留右侧操作区）

Rules（规则）:

- 返回入口固定左侧。
- 标题必须相对 Header 整体真正居中。
- 左右 Action（操作）区域保持对称 Layout Slot（布局槽位）。
- 右侧为空时仍保留布局占位。
- 使用统一 Detail Header 高度 Token。
- Touch Target（触控热区）>= 44px。
- 不显示 Global Brand / Theme / Bell。
- 普通详情页可与 Bottom Navigation 共存。

Frozen Contract（冻结契约）:

- 未经用户明确要求，不得修改其 Anatomy（结构）、返回按钮位置、标题居中方式、左右 44px Layout
  Slot（布局槽位）、Header Height（头部高度）、Padding（内边距）与 Safe Area Inset（安全区内缩）、
  Detail Header Title Typography Role（详情头部标题字体角色）、Touch Target（触控热区）或 Routing
  Contract（返回导航规则）。

### MobileGlobalHeader

Status（状态）: Frozen（已冻结）

Purpose（用途）: 一级 Mobile 页面统一品牌顶部栏

Anatomy（结构）: Brand Title（品牌标题） + Theme Action（主题操作） + Notification Action（通知操作）

Rules（规则）:

- 品牌固定左侧。
- Theme（主题）固定在 Bell（通知铃铛）左侧。
- Theme / Bell 使用对称 Touch（触控）体系。
- 不承载页面筛选或业务操作。
- 不显示明显底部分割线。
- 使用统一 Global Header Height Token（全局头部高度令牌）。
- 所有一级页面共用同一实现。
- 详情页面不得使用 Global Header。

Frozen Contract（冻结契约）:

- 未经用户明确要求，不得修改其 Anatomy（结构）、品牌左侧布局、Theme 位于 Bell 左侧且 Bell 位于
  最右侧的操作顺序、Header Height（头部高度）、Safe Area（安全区）所有权、Touch Target
  （触控热区）、一级页面使用规则或无底部分割线规则。

### MobileBottomNavigation

（移动端底部主导航）

Status（状态）: Frozen（已冻结）

Purpose（用途）: Mobile 五大一级功能模块的全局导航

Anatomy（结构）: 5 Equal Navigation Items（5 个等宽导航项）

Each Item（每项）: Icon Slot（图标槽位） + Label（文字标签）

Order（顺序）: 设备 / 任务 / 计划 / 店铺 / 我的

Rules（规则）:

- 5 个 Navigation Item（导航项）严格等分可用宽度，Active（选中状态）不得改变 Item 尺寸。
- Icon 位于上方，中文 Label 位于下方；Inactive（未选中状态）与 Active 必须有清楚结构语义。
- 图标视觉保持约 20～24px，整个 Item 的 Touch Target（触控热区）不得低于 44px。
- 普通一级页和普通详情页保持显示；`/devices/:deviceId` 选中设备，`/tasks/:taskId` 选中任务。
- 计划、店铺、我的分别由 `/schedules`、`/shops`、`/me` 选中，即使页面仍为建设中也不例外。
- 统一由 `MobileAppShell` Footer 管理，不随内容滚动；业务 Page 禁止私有实现或添加底部补偿魔法数。
- Bottom Safe Area（底部安全区）统一由 Shell Footer 消费，底栏自身不重复消费。
- 高度使用 `--layout-bottom-nav-height`，当前结构基线为 58px，再由 Shell 追加底部安全区。
- 普通详情页的 Back 继续由 `MobileDetailHeader` 负责；Bottom Navigation 用于一级模块快速切换，
  不是浏览器 Back。
- 未来只有运行配置、参数编辑、图片选择、AI 全屏工作台或全屏创作等明确沉浸式流程可通过
  统一 Route/Shell Contract 隐藏；本阶段不实现这些例外。
- 最终图标视觉暂不属于 Stage 1 冻结范围；当前允许继续使用 Vant Icon。
- Icon Slot 结构、位置、与 Label 的上下关系及语义属于 Stage 1 候选冻结范围。
- Final Iconography（最终图标体系）未来必须通过唯一 Icon Registry（图标注册表）统一替换，
  禁止各页面或业务模块分别引入不同来源。

Frozen Contract（冻结契约）:

- 未经用户明确要求，不得修改五入口结构及顺序、5 等分布局、Icon Slot 在上与 Label 在下的关系、
  Shell Footer 所有权、Bottom Safe Area、普通一级页与普通详情页显示规则、Device/Task 详情 Active
  映射、Touch Target 或 Routing Contract（路由约定）。
- 当前冻结不包含最终图标图案与颜色、字体最终 1～2px 调整、最终 Pressed（按压）效果、Shadow
  （阴影）或 Surface（表面）细节；这些分别留到后续 Stage 2、Stage 3 与 Stage 4。

### MobileSummaryStrip

（移动端概览横幅）

Status（状态）: Frozen（已冻结）

Purpose（用途）: 在一级列表页固定区域展示 2～4 个核心概览指标

Anatomy（结构）: Single Summary Surface（单一概览表面） + Equal Metric Slots（等宽指标槽位）

Each Metric（每项指标）: Icon Slot（图标槽位） ↓ Number Slot（数字槽位） ↓ Label Slot（标签槽位）

Rules（规则）:

- 支持 2～4 项；Device 当前按“在线设备 / 运行中 / 离线设备”使用 3 个严格等宽 Metric（指标）。
- Icon、Number（数字）与 Label（标签）垂直排列，并在各自 Equal Slot（等宽槽位）中整体水平、垂直居中。
- Icon 必须存在且位于 Number 上方；三个 Icon Slot 尺寸及垂直位置一致，不得挤压文字。
- Number 位于 Label 上方并承担最高信息权重；Label 固定中文、水平居中且保持单行。
- Number 只固定为比 Label 更强调的 Typography Role（字体角色）；具体字号与字重留到 Stage 2。
- 所有 Metric 共用一个 Summary Surface，不拆成独立 KPI Card（指标卡）。每项 Metric 支持可选
  Interactive Contract（交互契约）；有明确交互职责时使用可访问的 Button 语义，无交互职责时保持纯展示。
- 交互 Metric 的 Touch Target 不得小于 44×44px，视觉内容继续固定为 Icon → Number → Label，
  不得因 Button 语义改变三层结构或三等分布局。
- Device 三项 Metric 固定顺序为“在线设备 / 运行中 / 离线设备”，并正式承担对应快捷筛选职责。
  点击切换对应筛选；再次点击当前 Metric 恢复“全部”。
- Device Metric 与 `MobileListToolbar` Primary Selector 必须消费同一个 Filter State，禁止建立第二套
  Selected State、重复同步或各自独立过滤。
- 快捷筛选只能消费 Backend 已确认事实；服务端 Contract 不完整时，不得发送自造参数，也不得把
  当前分页的本地过滤伪装成完整筛选。
- Summary 位于业务 List 滚动区外，不随 Device Card 列表滚动。
- Loading / Error（加载 / 错误）只把未知值显示为 `—`，不得移除 Slot、改变顺序或改变整体高度。
- 正式 UI 只显示数字与名称，不显示统计口径、刷新频率、API、Mock 或实现说明。
- Separator（分隔）只能作为单一 Surface 内上下留空的弱分隔，不得贯穿全高或参与 Slot 宽度计算。
- Stage 1 只冻结 Icon Slot 的存在、位置与统一大小，不冻结最终图标造型、颜色、描边或资源来源。
- 具体 Typography 数值与最终高度留到 Stage 2；具体 Color / Surface / Shadow / Radius
  （颜色 / 表面 / 阴影 / 圆角）留到 Stage 3。
- 未来 Task、Shop、Schedule 只复用该结构；本阶段不实现对应页面或复杂 Dashboard Builder。

Frozen Contract（冻结契约）:

- 冻结 Single Summary Surface、三等分 Device Anatomy、Icon → Number → Label 顺序，以及 Device
  “在线设备 / 运行中 / 离线设备”的 Metric 顺序。
- 冻结可选交互能力、Device 快捷筛选职责、再次点击恢复全部、与 Toolbar Primary Selector 共用唯一
  Filter State，以及每项至少 44×44px 的 Touch Contract。
- 当前冻结不包含 Selected 视觉、Pressed 视觉、动画、最终颜色、最终图标、最终高度、间距和字体数值；
  这些继续由 Stage 2～4 定型。

## Light、Dark 与 System

Light 不使用“纯白页面 + 纯白卡片 + 灰色粗框”。`--bg-app` 提供柔和中性底色，
`--bg-surface` 承载主要 Section，`--bg-subtle` 承载次级区域，`--bg-surface-raised` 承载 Header、
Popup 与可触控 Card。Card 只使用柔和短阴影建立前后层级，不使用厚重悬浮或发光效果。

Dark 不是 Light 反色。深色值独立建立 Deep App Background、Surface、Secondary Surface 与
Raised Surface，避免纯黑背景、灰白粗边框和不可分辨的黑色卡片。阴影只使用深色透明度，
不使用灰白发光。

System 不建立第三套值。Theme Store 将 `system` 解析成当前 Light 或 Dark，并同步根元素
`data-theme`、`color-scheme` 与 Vant Dark Class。

## Surface、Text 与 Status

Surface 层级固定为：

| 语义              | Token                 | 用途                                   |
| ----------------- | --------------------- | -------------------------------------- |
| App Background    | `--bg-app`            | Shell 主内容背景                       |
| Primary Surface   | `--bg-surface`        | Cell、主要 Section                     |
| Secondary Surface | `--bg-subtle`         | Card 内次级摘要、折叠内容、输入底色    |
| Raised Surface    | `--bg-surface-raised` | Header、Bottom Navigation、Card、Popup |

文字至少区分 `--text-primary`、`--text-secondary`、`--text-tertiary` 与 `--text-disabled`。
主标题与核心值使用 Primary，描述与普通 Meta 使用 Secondary，时间、范围和最弱提示使用
Tertiary；不能仅靠字重制造层级，也不能以低对比度换取“高级灰”。

状态统一使用 `info / success / warning / danger / neutral`。默认视觉为“状态前景色 + 对应 Soft
Surface + 弱 Border”，避免浅色状态底配白字导致对比度不足。Running 使用 Info/Primary，Online、
Ready 与 Success 使用 Success，Offline/未上报使用 Neutral，Failed 使用 Danger。Feature 不得自行
选择蓝、绿、灰、红，也不得把不同 Backend 事实揉成一个视觉状态。

## Typography Scale

Mobile 使用同一字体栈和以下基础层级；字号、行高与字重都必须消费 Token，业务 Page/Feature 不得建立
局部字体体系：

| 层级                 | Size / Line Height | Weight | 用途                        |
| -------------------- | ------------------ | ------ | --------------------------- |
| Caption / Meta       | 12 / 16            | 400    | 时间、范围、最弱辅助信息    |
| Secondary            | 13 / 18            | 400    | 次级状态与普通辅助内容      |
| Action               | 13 / 18            | 500    | Button、Selector、轻量操作  |
| Body                 | 14 / 20            | 400    | 正文、Cell                  |
| Capability Name      | 14 / 20            | 500    | Application / Skill 名称    |
| Section / Card Title | 15 / 20            | 600    | Section、Toolbar、Card 标题 |
| Brand / Header       | 16 / 22            | 600    | 品牌与详情 Header           |
| Summary Number       | 18 / 22            | 700    | Summary 数字强调            |

对应 Size / Line Height Token 为 `caption`、`secondary`、`action`、`body`、`label`、`title`、
`display`，字重只复用 `regular / medium / semibold / bold` 四级。Action 与 Secondary 可以同字号，
但通过 500 / 400 字重区分操作与辅助内容；Capability Name 使用 Body 字阶 + Medium，不与 Section Title
争夺层级。品牌 Header 有存在感但不制造大标题；Summary 数字只承担数值层级，不能带动所有标题加粗。
日志技术值可使用 `--font-family-mono`，不使用 Windows 专属字体作为唯一字体。

## Spacing、Radius、Border 与 Shadow

Spacing 只使用 `--space-1/2/3/4/5/6/8`。页面水平 Padding 统一由
`--layout-page-padding-x` 控制，普通纵向间距由 Page Padding、Section Gap、Card Gap 和 Card
Padding 组合；禁止 Page 自行散落 13px、17px、19px 等魔法间距。

Stage 2B 的正式间距节奏如下；调整的是距离，不改变任何 Frozen Anatomy、滚动关系或控件高度：

| 语义                                |     最终值 | 用途                                                  |
| ----------------------------------- | ---------: | ----------------------------------------------------- |
| Page Horizontal Padding             |       16px | Header、Summary、Toolbar、List 与 Detail 统一左右留白 |
| Page Vertical Padding               |       12px | `AppPage` 基础上下留白                                |
| Section Gap                         |       12px | Device / Task Detail 一级区块间距                     |
| Card Gap                            |        8px | Device / Task 列表卡片间距                            |
| Card Padding                        |       12px | DeviceCard / TaskCard 统一内边距                      |
| Card Row Gap                        |        4px | 两类业务卡三行内容间距                                |
| Card Icon / Content Gap             |        8px | 两类业务卡及 DeviceRuntimeSummary 图标到正文          |
| Summary Gap / Padding               |  4px / 8px | Icon → Number → Label 与 Metric 内部留白              |
| Toolbar Group / Inner Gap           |  8px / 4px | 左右组之间与组内标题、Meta、操作间距                  |
| Runtime Summary Padding / Inner Gap | 12px / 4px | 上下分区内边距与分区内部行距                          |
| Capability Panel / Row Gap          |  4px / 8px | Header、Selector、List 与 Capability Row 内部节奏     |
| Header / Bottom Nav Inner Gap       |  4px / 4px | Header 操作间距与 Bottom Navigation 图文间距          |

`--space-*` 比例尺本身保持 4 / 8 / 12 / 16 / 20 / 24 / 32px。Stage 2B 只重映射既有语义，
没有建立 Device/Task 私有间距体系；Summary、Toolbar、Header、Bottom Navigation 与 Capability
Panel 的既有间距已经稳定，因此保持原值。

### Stage 2D Card / Icon Ratio（卡片与图标比例）

Stage 2D 只通过全局语义 Token 调整视觉图标尺寸与既有槽位宽度；不改变 Frozen Anatomy、卡片
Padding / Gap、行数、组件高度、Capability Panel / Row 高度或任何 Control 尺寸。Header、Detail Header
与 Bottom Navigation 继续消费 `--icon-size-default` 22px，Vant 映射不变。

| 语义                              | Token                                                                      |      最终值 | 用途                              |
| --------------------------------- | -------------------------------------------------------------------------- | ----------: | --------------------------------- |
| Card Leading Slot / Icon          | `--layout-card-leading-icon-slot-width` / `--icon-size-card-leading`       | 32px / 20px | DeviceCard、TaskCard 左侧视觉区   |
| Card Trailing Chevron Slot / Icon | `--layout-card-trailing-icon-slot-width` / `--icon-size-card-chevron`      | 24px / 16px | DeviceCard、TaskCard 右侧详情箭头 |
| Runtime Summary Slot / Icon       | `--layout-runtime-summary-icon-slot-width` / `--icon-size-runtime-summary` | 32px / 20px | DeviceRuntimeSummary 上下分区     |
| Capability Row Slot / Icon        | `--layout-capability-icon-slot-width` / `--icon-size-capability-row`       | 28px / 16px | Capability Row 左侧类型图标       |
| Summary Metric Icon               | `--icon-size-summary-metric`                                               |        20px | MobileSummaryStrip 的数字上方图标 |

图标视觉尺寸与槽位宽度是独立职责：较小、克制的图标置于稳定槽位中，既保证扫描起点一致，也不以图标
挤压名称、版本或右侧操作。Summary 的数字继续以 Display + Bold 承担最高层级；Metric Icon 仅提供语义提示。

### Stage 2E Controls（控件尺寸与触控比例）

Stage 2E 固定“视觉尺寸不等于 Touch Target（触控热区）”的控件尺度关系：外层语义 Button 负责至少
44×44px 的可点击范围，内部可见 Shell（外壳）负责轻量视觉。该阶段不改变 Frozen Anatomy、Typography、
Spacing、全局 Header / Detail Header / Toolbar / Bottom Navigation 高度、图标尺寸、Capability Panel / Row
高度，也不调整 Color、Radius、Shadow、Press 或 Motion。

| 控件角色                           | Visual Token / 最终视觉尺寸                 | Touch Target     | 消费位置                                      |
| ---------------------------------- | ------------------------------------------- | ---------------- | --------------------------------------------- |
| Compact Control（紧凑控件）        | `--control-height-compact` / 30px           | 外层 44px        | Toolbar Selector / Filter、Capability Refresh |
| Shared Icon Button（通用图标按钮） | `--control-size-icon-button` / 34px         | 外层 44×44px     | Theme、Bell、Detail Back                      |
| Capability Action（能力操作）      | `--control-height-capability-action` / 28px | 外层至少 44×44px | Configure / Run                               |
| Standard Control（标准控件）       | `--control-height-default` / 44px           | 44px             | Vant 默认 Button、Search Input                |

`MobileListToolbar` 的 Selector 与 Filter 保持同一视觉高度、同一垂直中心和独立 44px 命中区，宽度按内容决定；
360px 下必须同一行且热区不得重叠。Capability Row 保持既有 Icon Slot → Name / Version → Configure → Run
结构和五行可见规则；Configure / Run 仅缩小可见文字 Shell，不得成为大块 Button，也不得彼此抢占点击区域。
没有 `input_schema` 的 Business Skill 继续只显示 Run。

Capability Refresh 位于既有 Header 右侧，使用 30px 可见 Shell 与 44px 热区，作为 Section 级轻操作；Theme
与 Bell 使用相同的 34px 可见 Shell、44×44px 热区，并在固定 52px Global Header 内居中。Vant 统一映射的
默认 Button、Search、Tabs、Tabbar、NavBar、Tag、Field 与 Cell 尺寸不因紧凑业务控件而全局压缩：
`--van-button-default-height` 继续映射 44px，只由具备明确语义的 Shared / Entity 组件消费上述紧凑 Token。

圆角只使用 Control、Card、Overlay 与 Round 四级。Summary Card、Device Card、Task Card 使用
同一 Card Radius；Button、输入和 Card 内次级区域使用 Control Radius；Sheet/Popup 使用 Overlay
Radius。

普通 Card 使用 `--border-subtle`，需要清楚交互边界时才使用 Default/Strong Border。分隔优先依靠
Spacing、Surface 和 Typography。`--shadow-card` 只提供柔和浅层级，Pressed 使用
`--shadow-card-pressed` 收拢 Elevation；Header 不使用整条 Border 或 Shadow 分隔，Icon Button 使用
跨业务的 Raised/Pressed Shadow，`--shadow-tabbar` 只向上建立底栏层级，`--shadow-overlay` 只用于
真正 Elevated 的 Popup/Sheet。

## Shell、Header 与 Bottom Navigation

`MobileAppShell` 是全局背景、Viewport 高度链和顶部/底部 Safe Area 的唯一所有者。Shell Main
隐藏溢出，不再承担所有页面的滚动；List Page 的业务 List/Grid 与 Detail Page 的 `AppPage`
分别持有各自唯一内容滚动。`AppPage` 同时负责页面左右 Safe Area 与内容 Padding，业务 Page
不重复计算 Shell 边界。

`MobileGlobalHeader` 固定保留“思余AI中控台”、Theme Toggle 和通知入口，Theme 必须位于 Bell 左侧。
Header 使用 Raised Surface、克制的品牌字号和 44px 触控区域，通过 Spacing 与 Surface 自然过渡到
正文；禁止底部横线或明显整栏阴影。Theme 与 Bell 使用同一 Rounded Square Icon Button System：
透明 SVG 只承载图形，Raised Surface、圆角、柔和高光、阴影与 Press State 全部由 Mobile Token/CSS
控制，确保 Light/Dark 均不出现图片底色。
`MobileDetailHeader` 统一 Back、Route Title、高度、Surface 与分隔，Device/Task 详情不得自行实现返回栏。

Bottom Navigation 顺序固定为设备、任务、计划、店铺、我的。Active 只通过 Primary Icon/Label
清楚表达，不使用巨大色块、胶囊或 Glow；Inactive 使用 Tertiary。Vant Tabbar 非 fixed，Shell Footer
是底部 Safe Area 唯一所有者，每个入口触控高度至少 44px。普通 Device/Task Detail 同样保留该底栏；
只有未来参数编辑、图片选择、运行配置或全屏 AI 工作台等明确沉浸式流程允许隐藏。

## Card 与详情页原则

- Device Overview 使用一个三栏 Summary Surface；每项固定为 `Icon → Number → Label` 纵向结构，
  不拆成独立 KPI Card，也不使用解释 Meta、彩色 Dashboard Card 或 Button Chrome。
- Device Card 与 Task Card 共享 Surface、Radius、Border、Padding、Title、Meta、Status 与 Gap 语言。
- 列表长文本最多一行并省略；详情页显示完整内容，不用省略替代信息。
- Device Card 使用左侧图标、设备名 / 连接事实 / Meta 三行内容，以及右侧单一主要状态与 Chevron。
- Task Card 使用左侧图标、任务名 / 状态与时间 / Meta Tags 三行内容，以及右侧 Chevron；列表永不展示
  Progress 或 Current Message。
- 详情页按 Summary → 核心 Section → 主体内容 → More Information 形成纵向层级，不把全部信息塞入
  一张大 Card，也不回到 Desktop 左字段/右字段的管理表单感。
- Device ID、Task ID、Skill ID、Provider 技术字段和版本技术明细默认进入弱化的 More Information。

## 信息层级与产品文案

Mobile 正式 UI 展示结果，不解释实现。信息组织固定为少解释、少标签、少字段和高扫描效率：

- 列表页结果优先，只保留完成判断与操作所需的状态、数字、标题和弱 Meta。
- 详情页关键事实优先，必要诊断信息进入后续 Section，技术字段默认进入“更多信息”或 Debug。
- 能由位置、视觉层级或状态标签表达的含义，不再追加说明句。
- Loading、Empty 与 Error 各使用一个简短状态；网络 Error 不展示 HTTP、Axios、环境变量或 Backend 原因。
- 后台刷新失败保留上次成功内容，不用大段 NoticeBar 解释缓存、刷新周期或实现策略。
- 禁止在正式页面展示 Contract、API 限制、统计口径、字段计算方式、开发状态或未来架构说明。
- 失败原因、任务状态、运行日志、Worker 版本等影响用户判断的真实事实必须保留，不能以“少文案”为由删除。

## Vant Mapping 与 Shared UI

`mobile/src/shared/styles/vant-theme.css` 统一映射 Button、Tag、NavBar、Tabbar、Tabs、Cell、
CellGroup、Collapse、NoticeBar、Progress、Popup、Search、Field、Calendar、Picker、Empty、Loading 与
Skeleton。映射必须指向 Mobile Semantic Token，不保留与项目冲突的 Vant 默认蓝、灰、阴影或
低于 44px 的关键触控尺寸。NoticeBar 的状态使用全局 `mobile-notice-bar--success / warning /
danger` 语义 Class，不依赖 Vant 未公开属性，也不由业务页传入颜色值。

优先级仍为 Vant → `shared/ui` → 当前 Feature。只有跨 Device/Task 的真实语义、行为、可访问性或
重复配置存在时才新增 Shared UI；禁止建立 AppText、AppTitle、AppCard、AppSmallCard 等纯 CSS
代理，也禁止用 Page scoped/deep selector 重写 Vant 颜色。

## 触控、Focus、Safe Area 与未来 Capacitor

- Button、Back、Bell、Bottom Nav、Card Click、Collapse 与 Calendar Action 的语义触控目标至少 44px。
- 所有键盘可交互元素统一消费 Focus Ring Token；Hover 只作为辅助，不能成为唯一反馈。
- 使用 `100dvh` 构建手机高度链并保留 `100vh` 回退，不通过 `100vh - x` 猜布局高度。
- 顶部/底部 Safe Area 归 Shell，左右 Safe Area 归 Header/AppPage/List/Sheet 各自既定边界；不得重复消费。
- 禁止横向溢出和无必要的嵌套滚动区。
- 当前保持 Web First；实现不得依赖 Electron、Node、Windows API 或桌面 Hover，确保未来可由
  Capacitor 承载而无需重写 Design System。本轮不实现 Capacitor、iOS 或 Android 壳。

## Mobile Layout System

### Page Pattern

Mobile 页面只使用以下三种 Pattern：

1. **List Page**：Global Header → 可选 Summary Strip → List Toolbar → Scrollable List/Grid →
   Bottom Navigation。Header、Summary、Toolbar 与 Bottom Navigation 均不随业务卡片滚动。
2. **Detail Page**：Detail Header → Scrollable Detail Content → Bottom Navigation。详情隐藏 Global
   Header，但保留全局 Bottom Navigation；内容顺序固定为 Summary → Sections → More Information。
3. **Future Workspace Page**：为 AI 等高交互工作台保留，未来独立设计；不得为了复用而强塞 Summary
   或 List Toolbar。本轮不实现 Workspace。

List Page 使用 Flex/Grid 高度链与 `min-height: 0`，不使用多组 `position: fixed`、手工 `top/bottom`
或 `100dvh - x`。Shell Main 隐藏溢出，`.mobile-list-page__scroll` 是唯一业务滚动容器；Detail Page
由 `AppPage` 持有唯一内容滚动。

### Global Header、Detail Header 与 Bottom Navigation

- Stage 2C 复核后，Global Header 保持 52px，另由 Shell 消费顶部 Safe Area；内容固定为品牌、Theme、Bell。
- Detail Header 保持 50px，另由 Shell 消费顶部 Safe Area；Device/Task 不得各自改高度。
- Bottom Navigation 保持 58px，底部 Safe Area 只由 Shell Footer 消费；顺序固定为设备、任务、
  计划、店铺、我的。
- 三者均位于业务滚动区外，不需要 `position: fixed`，也不得由业务 Page 复制实现。普通 List、Detail、
  Logs 与 Status 页面均保留底栏；未来沉浸式 Route 必须显式声明例外。

### Summary Strip Pattern（概览横幅模式）

`MobileSummaryStrip` 在 Stage 2C 依次实测 98px、92px、88px、84px 后，统一高度确定为 88px：既保留
Icon、Value、Label 三层的完整居中关系，也避免首屏出现 Dashboard 式的多余留白。它使用统一页面水平 Padding
和一个整体 Surface，内部承载 2～4 个等宽 Metric，推荐不超过 3 个。
每项只包含 Icon、Value、Label 与可选 Tone，并按 Icon → Value → Label 垂直排列；禁止解释文字、统计口径和
刷新说明。每个 Metric 可按领域职责选择纯展示或可交互；交互项使用 Button 语义和至少 44×44px Touch
Target，但当前不冻结 Selected / Press / Motion 视觉，也不拆成三张独立 Dashboard Card。
未来 Task、Shop、Schedule 需要摘要时复用同一组件，不新建业务 Summary Card。

### MobileListToolbar

（移动端列表工具行）

Status（状态）: Frozen（已冻结）

Purpose（用途）: 列表型一级页面的固定列表控制行。

Anatomy（结构）:

- Left Group（左侧组）: Title（标题） + Meta（辅助信息）。
- Right Group（右侧组）: Primary Selector（主选择器，可选） + Filter Action（筛选操作，可选）。

Rules（规则）:

- 工具行只有一个水平布局行；Title + Meta 在同一左侧组，Primary Selector 位于 Filter Action 左侧。
- 360 / 375 / 390 / 430px 均不得换行或横向溢出；空间不足时优先缩短 Meta 和 Selector 文案、收紧 Gap 或
  Ellipsis，不缩小 Touch Target。
- 不使用外部 Card、大圆角、Card Border、Raised Surface、大 Shadow 或独立大面积背景块。
- Primary Selector 和 Filter Action 是同等级的轻量控件，不得把其中一个放大为 Primary Button。
- Visual Size 与 Touch Target 分离；当前使用 44px 命中区与 30px 紧凑视觉控件作为 Stage 2E 实现基线。
  本阶段只收口控件尺寸，不调整既有 Spacing 与 Typography 基线。
- 工具行位于 Business List（业务列表）滚动区之外；只有列表滚动，工具行不随 Card 滚动，并复用统一隐藏滚动条规则。
- Initial Loading / Error / Empty 只替换列表区状态，不移除或改变工具行 Anatomy。
- Device Summary 与 Primary Selector 消费唯一 `DeviceQuickFilter` 状态；Summary 切换在线/运行中/离线时，Selector
  同步显示“在线 / 运行中 / 离线”，再次选择当前 Metric 恢复“全部”。
- Shared 组件只接收 `title / meta / selector / filter` 并触发操作事件，不识别 online、offline、task status、
  device id 或 date range，不承载领域业务逻辑。
- Backend Device List 当前只支持 `page / page_size`；不发送自造筛选参数，也不把当前分页过滤伪装成完整筛选。本地快捷
  筛选只在全部分页和所需事实完整时开放，该限制继续记为 Contract Gap。
- 最终 Color / Radius / Shadow 留到 Stage 3，Pressed / Motion 留到 Stage 4。
- 修改上述 Anatomy、单行布局、滚动边界或领域状态边界前必须由用户明确解冻。

### DeviceCard（设备卡片）

Status（状态）: Frozen（已冻结）

本节术语统一为 Leading Visual（左侧视觉区）、Main Content（主要内容区）、Trailing Area（右侧区域）、
Chevron（右箭头）、Meta Row（辅助信息行）、Meta Tags（辅助标签）、Content Slot（内容槽位）与
Hierarchy（信息层级）。

Anatomy（结构）:

- Leading Visual: 独立 Device Icon Slot；固定在左侧、与内容垂直居中且不参与正文换行。
- Main Content: 第一行 Device Name，第二行 Primary Runtime State，第三行 Meta Row。
- Trailing Area: 一个 Primary Status / State Chip 与固定右侧、垂直居中的 Chevron。

Rules（规则）:

- Device Name 单行 Ellipsis；Runtime State 只消费正式连接事实，不能伪造设备类型或系统信息。
- Meta Row 单行、最多两个简短正式事实，当前可使用心跳与 Worker 版本；允许以后替换为 Provider 摘要等
  真实字段，但不得增加第四行或改变 Hierarchy。
- Trailing 只显示一个主要状态，例如空闲、执行中或停用；不得堆叠多个大型 Tag 或挤压名称。
- 整张 Card 是唯一 `/devices/:deviceId` 入口；列表中的 Active Task 不覆盖整卡，也不直接进入 Task Detail。
- Frozen Contract（冻结契约）只覆盖 Icon Slot 的存在与左侧位置、Main Content 三行 Content Slot、
  Trailing Status / Chevron、单行约束及整卡进入 Device Detail 的导航关系。
- Non-Frozen（非冻结）范围包括 Icon Slot 最终宽度、Icon 尺寸与图案、Content Gap、左右 Padding、
  Typography、Card 最终高度、Radius、Shadow、Color、Surface、Tag 质感与 Pressed State；Stage 2～4
  可统一调整这些值，而无需解冻 1F。

### TaskCard（任务卡片）

Status（状态）: Frozen（已冻结）

Anatomy（结构）:

- Leading Visual: 独立 Task Icon Slot；固定在左侧、与内容垂直居中且不参与正文换行。
- Main Content: 第一行 Task / Execution Name，第二行 Status + Time，第三行 Meta Tags。
- Trailing Area: 固定右侧、垂直居中的 Chevron。

Rules（规则）:

- Task Name、Status + Time 与 Meta Tags 都保持单行；长标题与长 Meta 使用 Ellipsis，不得撑高 Card。
- Meta Tags 最多两个，只能来自正式业务事实；具体字段以后可替换，但不得增加第四行或改变 Hierarchy。
- No Progress in List Card（列表卡片不显示进度）：即使 Backend 返回结构化 Progress，也不渲染进度条、
  `current / total` 或 Current Message；执行过程进入 Task Detail 的 Runtime Log。未来若要恢复列表进度，
  必须重新解冻 Step 1F。
- 整张 Card 是唯一 `/tasks/:taskId` 入口，不额外显示“查看 / 详情”按钮。
- Frozen Contract 只覆盖 Icon Slot 的存在与左侧位置、Main Content 三行 Content Slot、右侧 Chevron、
  单行约束及整卡进入 Task Detail 的导航关系；列表不显示也不预留 Progress 行。
- Non-Frozen 范围包括 Icon Slot 最终宽度、Icon 尺寸与图案、Content Gap、左右 Padding、Typography、
  Card 最终高度、Radius、Shadow、Color、Surface、Tag 质感与 Pressed State；Stage 2～4 可统一调整。

DeviceCard 与 TaskCard 共享同一个 Mobile Business Card Pattern，但继续保留各自领域组件；禁止创建
`UniversalMobileCard`、`GenericBusinessCard` 或 Entity Card Builder。

#### TaskCard Reuse Contract（任务卡复用约定）

- Task List 与 Device Detail 的 Current Task 都直接渲染同一个 `TaskListCard` 领域组件，视觉与结构只有
  一个来源。
- 页面上下文只负责把正式 Active Task 数据做最小适配，并提供进入 Task Detail 与返回 Device Detail 的
  导航关系；`TaskListCard` 不感知来源页面。
- Device Feature / Page 禁止复制 Task Card Template、CSS 或创建 `CurrentTaskCard`、`DeviceTaskCard` 等
  第二套业务卡片。无 Active Task 时只显示 Section Title 与“空闲”，不渲染假 Task Card。
- 后续 Stage 2～3 对正式 Task Card 的尺寸、字体、颜色、圆角或 Surface 调整必须自动同步到两个使用场景。

### Scroll Container 与隐藏 Scrollbar

正式主业务滚动区统一使用 `.mobile-scroll-container`。该规则通过 `scrollbar-width: none`、
`-ms-overflow-style: none` 与 `::-webkit-scrollbar` 同时覆盖 Firefox、旧 Edge 和 Chromium/WebKit，
只隐藏视觉 Scrollbar，不改变 `overflow-y: auto`，也不裁切内容。触控、滚轮、触控板和键盘滚动必须
继续可用。List Page 的 List/Grid 与 Detail Page 的 `AppPage` 使用该规则并提供具名键盘焦点入口；
Body/Document 不承担业务滚动。

### Card 与 Detail Section Pattern

- Device Card 与 Task Card 的 Step 1F Frozen 结构以本文对应组件章节为唯一来源；不得回退到当前任务行、
  Current Message 或列表 Progress。
- Name、State / Time 与 Meta 在列表只占一行并 Ellipsis。Card 通过统一 Padding、Line Height、Gap、
  行数和 Min Height 获得稳定尺寸，不写死统一 Height。
- Device/Task 共享 Card Padding、Radius、Border、Surface、Title/Meta Line Height、Card Gap 与 Press，
  但继续保留 Entity/Feature 级组件，不新增万能 `MobileCard` Wrapper。
- Detail Section 使用 Section Title → Section Content；Title/Content Gap 与 Section Gap 均消费统一 Token，
  最大视觉 Surface 层级为两层，避免 Card 套 Card。
- Device Detail 顺序固定为 DeviceRuntimeSummary → Capability Panel → Current Task → More Information。
  DeviceRuntimeSummary 使用单一 Card 的上下两段；设备运行事实在上，影刀账号事实在下，UUID、内部状态
  与发现时间进入 More Information。
- Device Capability Panel 是 Device 领域组件，不属于 Shared UI。第一行固定 Section Title“能力”和
  轻量刷新 Icon Action，第二行使用“影刀应用 / Skills”50/50 Segmented Control；内容区固定五行高度
  并独立滚动，每行稳定为 `Name + Configure + Run`。Skill 没有
  `input_schema` 时不显示无意义 Configure，Internal Skill 不进入普通用户核心列表。
- Application/Skill 名称单行省略并为右侧 Actions 保留空间；Application ID、Skill ID 与其它 UUID 不得
  出现在默认产品 UI。未接入正式 Backend Contract 时刷新、配置与运行仅允许显示“功能建设中”，不得
  显示应用已启动、能力已刷新或参数已保存等 Fake Success。

### Summary Stacked Metric（概览纵向指标）

Summary Metric 固定使用 `Icon → Number → Label`。Icon Slot 统一大小，Number 使用 Display 字阶与 Bold，
Label 使用 Caption 与 Secondary Text；三栏等宽、各自整体居中且 Label 保持单行。分隔只允许使用上下留空的
弱 Vertical Separator。无交互职责时保持展示语义；有交互职责时获得 Button 语义和 Touch Contract，
Selected / Press / Motion 的最终视觉留到 Stage 4。Metric Icon 统一使用
`--icon-size-summary-metric` 20px，不与 Display 数字争夺信息层级。

### DeviceRuntimeSummary（设备运行摘要）

Status（状态）: Frozen（已冻结）

Purpose（用途）: Device Detail 首个核心摘要组件，让用户第一眼判断设备、连接、当前运行、Worker、影刀
登录与当前账号；它不承担 Capability、Application List、Skill、Current Task Detail 或完整技术诊断。

本节术语统一为 Single Summary Card（单一摘要卡片）、Upper Section（上半区）、Lower Section（下半区）、
Separator（分隔）、Icon Slot（图标槽位）、Main Content（主要内容）与 Meta Slot（辅助信息槽位）。

Anatomy（结构）:

- Single Summary Card 内固定为 Upper Section → Separator → Lower Section，不拆成两张 Card，也不在下段
  嵌套 Account Card。
- Upper Section 使用 Device Icon Slot + Device Main Content；Main Content 固定三层：Device Name、
  Connection State + Runtime State、Device Meta Slot。
- Lower Section 使用 Account Icon / Avatar Slot + Account Main Content；Main Content 固定两层：第一行
  “影刀账号” + Login Status，第二行 Account Display Name + Yingdao Version（影刀版本）。账号名与版本
  使用轻量分隔符并保持同一水平行。
- Separator 是与 Card 内边距对齐的弱横向分隔，只分区而不形成表格或第二张 Card。

Frozen Contract（冻结契约）:

- 冻结范围只包含单一卡片、上下顺序、两段各自左 Icon / 右 Content、Upper 三层 / Lower 两层 Hierarchy、
  Separator，以及 Device / Provider / Account UUID 不进入正常 Summary。
- Device Name 与 Account Name 单行 Ellipsis；账号名称允许收缩，但影刀版本必须保持可见。状态只使用正式
  Device、Active Task 与 Provider Account Contract，不推断 OS、设备型号、账号创建日期或其他不存在字段。
- Device Meta 当前可使用 Worker 版本与 Heartbeat；Lower 第二行从正式 `provider_version` 读取版本值，
  正常 UI 只显示“账号名称 · 版本号”，不显示 `Provider` 文案。账号类型、企业账号、发现时间及其它 Provider
  技术字段统一进入 More Information（更多信息）。
- Summary 跟随 Device Detail Content 滚动，默认仅展示摘要；不新增设备、账号、Provider 或设置跳转。
- 该组件属于 `features/device-center`，禁止抽成 `UniversalSummaryCard`、`EntityRuntimeSummary` 或 Shared UI。

Non-Frozen（非冻结）范围包括 Card 最终高度、Upper / Lower 高度比例、Icon Slot 宽度、Icon 尺寸与图案、
左右 Gap、上下 Padding、Typography、Separator 颜色与长度细节、Radius、Shadow、Surface、Status 颜色及
Account Avatar 最终样式；Stage 2～3 可统一调整这些值，而无需改变 1G Anatomy。

### CapabilityPanel（能力面板）

Status（状态）: Frozen（已冻结）

Purpose（用途）: Device Detail 中查看影刀应用与 Business Skill（业务 Skill），并为正式 Refresh
（刷新）、Configure（配置）和 Run（运行）业务链保留入口；当前未接 Mutation 的入口不得伪造成功。

Anatomy（结构）:

- Capability Header（能力标题区）：左侧标题“能力”，右侧 Refresh Icon Action（刷新图标操作）。
- Capability Type Selector（能力类型选择器）：同一行、等宽的“影刀应用 N”和“Skills N”，顺序固定，
  Active / Inactive（选中 / 未选中）结构与 Count（数量）必须存在。
- Scrollable Capability List（可滚动能力列表）：仅 Capability Row（能力行）参与内部滚动；Header 与
  Selector 固定在面板内，不随列表滚动。
- Capability Row 固定为 Leading Icon Slot（左侧图标槽位） + Main Content（主要内容） + Trailing
  Actions（右侧操作）。Main Content 显示单行 Name 与正式 Contract 存在时的 Optional Version
  （可选版本）；Actions 固定 Configure 在左、Run 在最右。

Frozen Contract（冻结契约）:

- 影刀应用只读取正式 `app_name`；当前 Contract 只有技术 `version_id`，因此正常列表不把它当可读版本。
  Skills 只展示 `classification=business`，并可读取正式 `version`；Internal Skill（内部 Skill）不进入
  普通用户核心列表。
- 所有能力行都有统一 Icon Slot，图标不参与名称换行；长名称单行 Ellipsis，Actions 必须保持可见。
- Skills 只有在 `input_schema !== null` 时显示 Configure；无参数 Schema 时只显示 Run。Configure 属于
  当前 Application / Skill，不建立 Device 级全局参数入口。
- 面板默认完整显示五行，第六行开始在 Capability List 内部滚动，不得露出半行；Header 与 Selector
  不滚动。内部列表复用 `.mobile-scroll-container` 隐藏 Scrollbar，并在边界后自然交还 Detail Page，
  形成 Nested Scroll（嵌套滚动）而不锁死外层页面。
- Selector 自身必须完整落在固定的 Vant Wrap（包裹层）内；外框、圆角、文字与 Active Surface 不得被
  `overflow` 裁切。修复 Selector 盒模型不得挤占五行 Capability List，也不得把 Header / Selector 移入
  内部 Scroll Area（滚动区域）。
- Application UUID、Skill ID、Provider ID、Execution ID 不进入正常列表；技术 ID 只进入 More
  Information（更多信息）或 Developer（开发者）层。
- Capability 图标未来由 Icon Registry（图标注册表）统一解析：显式 `icon_key` → 业务/类型映射 → 默认
  Capability 图标。Feature / Page 禁止按名称散落导入 PNG/SVG。本阶段只建立统一 Icon Slot 与类型占位图标，
  不实现用户选图、上传资源或 Backend 图标配置。
- Refresh、Configure、Run 必须复用正式 Backend Contract；当前无正式 Mutation 时只保留入口，不猜 URL、
  DTO 或 Mobile 专属执行链，也不显示“已刷新”“已保存”“已启动”等 Fake Success（伪成功）。
- Device Detail 的 Current Task 固定复用正式 `TaskListCard`；上下文只影响 Active Task 数据适配与返回导航，
  不允许出现第二套 Current Task Card 结构。

Non-Frozen（非冻结）范围包括最终 Icon、Icon Slot 最终宽度、Row 最终高度、Panel 最终像素高度、
Typography 具体值、Configure / Run 最终按钮尺寸、Selector 最终视觉、Color、Radius、Shadow、Press 与
Motion。Stage 2～4 可统一调整这些值；当前实现数值不构成冻结契约。

### Loading、Error 与 Empty

Initial Loading、Initial Error 与 Empty 只替换 `.mobile-list-page__scroll` 内的业务内容。Global Header、
Summary（无法统计时显示 `—`）、List Toolbar 与 Bottom Navigation 始终保留，状态切换不得改变 Shell
高度或滚动所有权。列表底部只使用正常内容 Padding；Shell 已排除 Footer，禁止额外手工垫入 Bottom
Navigation 高度。

未来 Shop、Schedule 与 Asset List/Grid 必须复用相同 Fixed Area + Scroll Region 结构；Grid 只替换
业务滚动区域，不改变 Header/Summary/Toolbar/Bottom 的职责。

`/__foundation` 仅在 Development 注册，用于验证 Token、Surface、Typography、Soft Status、Vant、
Light/Dark/System、Focus、Touch 与 Safe Area；Production 不得包含该 Route。
