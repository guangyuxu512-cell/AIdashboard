# Mobile 任务中心规范

## 1. 范围与分层

Task Center V1 只读，提供 `/tasks` 列表与 `/tasks/:taskId` 详情，不提供创建、取消、重试、删除或任务编排。

```text
pages/tasks
├── features/task-center  筛选、刷新、无限列表
├── features/task-runtime 事件游标、运行时投影、结果/日志展示
├── entities/task         DTO、API、Mapper、Query、状态语义、卡片
└── entities/device       DTO、分页/详情 API 与 Query
```

Page 只做组合；Feature 不互相导入内部实现；所有请求经 Entity API 到唯一 `shared/apiClient`。测试 Fixture 只能位于 `tests/**`。

## 2. 列表与筛选

- 主状态使用 Tabs：全部、待执行、执行中、成功、失败、已丢失；其中“已丢失”是本轮产品指定文案。中文映射和类型只能由 Backend `TaskStatusDto` 派生，Task Entity 维护唯一一份映射。
- 搜索、设备和日期位于底部 Filter Sheet。
- 日期预设固定为今天、昨天、最近 7 天（默认）、最近 30 天、自定义、全部时间。除自定义外不打开 Calendar；有日期的预设均按本地自然日发送 `[created_from, created_to)` 半开区间，“全部时间”完全省略两个参数。
- 搜索最多 500 字；设备普通选项只展示设备显示名，不把 UUID 当作用户标签。
- 执行名称按 `execution_display_name → skill_display_name → skill_id` 防御性回退；正式主字段为 `execution_display_name`。
- Infinite Query 严格保持 Backend 稳定分页顺序，并按 `task_id` 去重。
- 下拉刷新收敛到第一页；仅有一页时每 5 秒后台刷新，加载第二页后停止自动刷新。
- 是否为缓存背景错误以 Query 是否存在成功数据判断，而非当前列表长度；成功空列表的背景失败仍保持 Empty 并显示 NoticeBar。
- Task 下一页失败只在列表尾部提示并提供明确重试，不升级为顶部背景错误，也不由 List 自动循环请求。
- Device Picker 每页 100 条并可继续加载，直到服务端 `total`；禁止固定取前 100 条。它的首屏、缓存背景与下一页错误分别处理，下一页失败在尾部明确重试。

## 3. 详情与安全展示

首屏展示执行对象、状态、设备、创建/开始/结束时间、耗时、结构化进度、当前信息和店铺数量；任务 ID、技能 ID、设备 ID 放入“更多信息”折叠区。

- 详情 DTO 不含设备显示名，深链也必须通过 `GET devices/{id}` 查询。
- 结构化进度只读取 `event_type=progress` 的 `metadata.current/total`，不得从日志文本猜测数字。`current` 必须是非布尔整数且 `>= 0`；`total` 只能为 `null`，或为非布尔整数且 `> 0`、`current <= total`；任一无效时整条进度返回空，列表与详情统一显示“—”。
- 当前信息只按 `progress → status → log` 类型优先级取各类型最新非空消息，不给 `completed/failed` 自定义优先级。
- Success 只展示非空 `result.summary`，否则展示“任务已成功完成”；禁止通用展开 `result` 或 `input`。
- Failed/Lost 只展示 Backend 已脱敏的 `error_message` 和可选 `error_code`。

## 4. 运行日志

- 首次请求最近 100 条；加载更早日志使用 `before_seq`；非终态增量使用 `after_seq`。
- Event 按 `seq` 去重并升序展示。非终态每 2 秒请求增量；终态无论先拿到 Status 还是初始 Event，都必须在初始窗口后执行一次连续 final sweep。直接深链打开终态详情同样执行。
- Final sweep 以服务端 `next_after_seq` 连续请求，每批最多 100；仅在单批少于请求上限、游标不前进或页面已释放时停止。同一详情只能有一个 drain 执行，竞态信号合并为后续串行 drain；错误保留已有 Event 并显示背景重试。
- 不引入 WebSocket/SSE。日志始终按纯文本渲染，不解析 HTML 或日志内容。
- 页面最多保留最新 500 条 Event。`before_seq` 加载更早时按剩余容量收敛；`after_seq` 不受剩余容量阻断，增量超过上限时持续拉取并滚动淘汰最早项，同时明确提示。
- 保留状态必须由清理标记和当前 Event 共同判断：从未产生、完整保留、已清理且为空、已清理但仍有保留部分。
- 初始 Event 响应成功前不显示任何保留状态，避免 Loading/Error 阶段声称“从未产生日志”。

## 5. Mobile UI

优先使用 Vant Tabs、Search、List、PullRefresh、Popup、Field、Calendar、Cell、Tag、Skeleton、Empty、NoticeBar、Collapse、Loading 与 Progress。任务列表使用触控卡片，详情是完整页面而非 Drawer/Sheet。

业务样式只消费现有 Mobile Token；不得添加 Task 私有 Token 或颜色字面量。任务 Tabs、Toolbar、卡片列表、筛选 Popup 与自定义 Calendar 消费左右 Safe Area，设备 Popup 同时消费底部 Safe Area。底部导航以非 fixed 行参与 `MobileAppShell` Grid，且只由 Shell 消费底部 Safe Area；详情隐藏底部导航并显示返回动作。长错误码必须允许折行，`/__foundation` 继续保持 DEV-only 且不进入导航。

Running 详情的耗时用轻量本地时钟更新；任务进入终态或页面卸载时停止定时器，不为时钟发送额外写请求。

## 6. 验证

单元/组件测试覆盖 Contract、Mapper、状态、日期、Query 参数、分页/去重/刷新策略、列表状态、五状态结果、结构化进度、日志游标/终态/清理/上限及 Route Meta。

Mock E2E 覆盖列表、状态/设备/日期/搜索、滚动更多、下拉刷新、详情深链、运行日志、返回，并在 360/375/390/430 宽度与 Light/Dark 下验证 Console Error 为零、无横向溢出和触控高度。
