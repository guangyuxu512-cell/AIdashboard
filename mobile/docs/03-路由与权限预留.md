# Mobile 路由与权限预留

## Router

Mobile 统一使用 Vue Router Hash History，所有 Route 只在 `src/app/router/` 注册。

每条 Route 必须显式声明：

```ts
interface RouteMeta {
  title: string
  layout: 'main' | 'detail'
  requiresAuth: boolean
  permission: string | null
}
```

不得省略 Meta 后依赖隐式默认值。Backend 尚未定义权限码时，`permission` 必须为 `null`，
禁止使用预想字符串占位。

## Foundation Route

`/__foundation` 是基础设施验收页：

- 仅在 `import.meta.env.DEV` 为真时注册。
- Production Route Table 不包含该路径。
- 不进入产品导航。
- 不请求 Backend，不展示虚构业务数据。

根路径 `/` 始终注册，显示 Mobile 产品落地页并通过底部导航进入正式业务。

## 产品路由与导航

- `/tasks` 是完整任务列表页；`requiresAuth: false`、`permission: null`。
- `/tasks/:taskId` 是完整任务详情页；`requiresAuth: false`、`permission: null`。
- `/devices` 是只读设备列表页；`requiresAuth: false`、`permission: null`。
- `/devices/:deviceId` 是只读设备详情页；`requiresAuth: false`、`permission: null`。
- `/schedules`、`/shops`、`/me` 共用统一建设中页，分别显示“定时计划”“店铺”“我的”；不请求业务 API。
- `layout=main` 统一显示“思余AI中控台”品牌 Header；`layout=detail` 统一显示 Detail Header。两类普通
  页面都保留固定顺序“设备、任务、计划、店铺、我的”Bottom Navigation。
- 任务与设备详情复用相同返回组件；设备当前任务继续跳转现有 `/tasks/:taskId`，并保留
  `fromDeviceId` 返回来源。未来只有运行配置、参数编辑、图片选择或全屏工作台等沉浸式 Route 才允许
  通过正式 Shell Meta 隐藏底栏；当前不建立假沉浸式路由。
- `layout` 只描述 Shell 行为，不替代 `requiresAuth` 或 `permission`。
- 这些 Route 不安装 Fake Auth；未来正式身份 Contract 落地时必须统一调整 Guard，不能在页面内临时鉴权或猜测 `device.read` 等权限码。

“我的”当前只是占位。未来 Human Auth Contract 完成后，才允许承载 Current User、Theme、Account
与 Logout；本阶段不创建假用户、假头像、假账号或 LocalStorage 用户。

Global Header 的通知图标当前只提供统一入口与“通知功能建设中”提示，默认无 Badge/Dot，不建立
Notification Center 或假通知数量。

## Auth 与 Permission

当前没有正式员工 Authentication、JWT、Session 或 RBAC Contract，因此：

- 不创建 Auth Store。
- 不生成或保存假 Token。
- 不编造 Login、Forbidden 路由或权限码。
- 不安装允许所有请求通过的假 Guard。

`installRouteAccessGuards(router, { authGuard, permissionGuard })` 提供两个命名明确的注入点，
并固定按 Authentication Guard、Permission Guard 的顺序注册。正式身份 Contract 落地后，
应用启动层才显式注入真实实现；当前 Router 不调用该函数，也不自行读取 Backend、
localStorage Token 或 Worker Device Token。

未来页面访问链固定为：

```text
Login
↓
Session / JWT
↓
Current User
↓
Mobile Router
↓
Auth Guard
↓
Permission Guard
↓
Page
```

未来 API 认证链固定从唯一 Client 插入：

```text
Mobile API Client
↓
Authorization Header Interceptor
↓
Backend API
↓
Backend Real Permission Guard
```

Mobile 只保留完整 Authorization Header 的 Provider Hook，不猜 JWT 格式、刷新 URL 或 Token
生命周期。User Authentication 与 Worker Device Token 是两套独立身份，永不复用。

Frontend Permission 仅改善页面体验，不是安全边界。Backend 必须独立执行 Authorization 和
Data Scope；Mobile 不得获取全量数据后在本地实现数据权限。
