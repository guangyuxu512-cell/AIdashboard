# 权限与安全

推荐：RBAC + Data Scope。

权限至少考虑：
- 菜单
- 动作
- 店铺范围
- 数据范围

## Human Access 与 Worker Identity

Human Management Plane 的身份流为：

```text
Human Authentication → HumanPrincipal → Active Membership → ActorContext
```

Worker Execution Plane 继续使用：

```text
Bearer Worker Token + X-Device-ID → WorkerPrincipal
```

两条身份链不能互换。TeamMembership 不进入 Worker Heartbeat、Claim、Capability 或 Asset Download
鉴权；Worker 只消费 Backend 已经完成 Human Scope 校验后创建的 Task。当前 Human Login
Identifier Contract 尚不存在，因此 Access API 的 Human Principal 入口默认拒绝请求，不使用
Worker Token、任意 User ID Header 或未认证前端状态补位。

Data Scope V1 只有 SELF、TEAM、ALL。ALL 必须来自明确 Membership 配置；数据库未知值和代码未知
值都必须 fail closed。Role 与 Scope 独立，`member` 不自动等于 SELF/TEAM/ALL 中任何一个。

## Credential
账号密码属于 Shop/Account Credential，不属于某台 PC 的永久明文配置。Worker 只允许在已认证、
已领取且明确关联有序 `shop_ids` 的单个 Task Claim 中取得本次执行所需 `accounts`；这不是设备
批量下载凭证，且不得长期保存或写入日志、Runtime Event、Result。

外部 Application 即使误把完整 `account.json` JSON 写入 tasklog，Backend 在 Runtime Event 入库前
也必须识别英文多账号 Payload 和中文 `店铺列表/登录账号/登录密码` 结构，并将整段替换为
`[ACCOUNT_PAYLOAD_REDACTED]`；带引号的 JSON 字段和普通 `key=value` 文本都必须走同一脱敏边界。

## Session
Session 独立建模：
- cookie
- token/csrf（需要时）
- user_agent/profile
- version
- status
- source_device
- updated_at

## Worker 授权
Worker 只可读取：
- 当前 Task
- 当前授权 Shop
- 当前执行所需凭证

禁止下载所有账号密码、所有 Cookie。
前端禁止显示完整凭证。
敏感读取和变更应有 Audit。

阶段 3A 使用 Fernet（`cryptography`）和服务器环境变量 `BACKEND_ENCRYPTION_KEY` 加密 Credential Secret 与 Session payload。密钥不得提交 Git；缺少或无效密钥时敏感写入必须失败，不允许退化为明文。

API 错误会按敏感字段名脱敏验证输入。日志、异常、`repr` 和审计均不得携带密码、验证码、Cookie、Token 或 Session payload。普通 Frontend 只能访问脱敏 Credential 状态和 Session 元数据。

## Webhook Secret 与 Worker 撤销

Webhook URL 具有直接发消息能力，按 Credential Secret 同级处理：使用 SecretCipher 加密落库，不进入读取 DTO、日志或前端 Query Cache。设备软移除时 Worker Credential 仅置为 disabled/revoked，保留审计历史；旧 Token 对全部 Worker Endpoint 统一认证失败。
