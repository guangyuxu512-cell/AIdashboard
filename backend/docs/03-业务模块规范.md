# 业务模块规范

## API
负责参数解析、权限入口、调用 Service、返回 Schema。

API 是未来 Human Authentication、Permission Guard 与 Data Scope 的插入边界。Router 禁止直接完成核心业务写入或跨 Repository 编排事务。

## Service
负责业务规则、跨 Repository 协调、事务边界。

后台 Scheduler / Maintenance 也必须复用正式 Service；后台入口不因绕过 HTTP 而获得绕过业务规则的资格。

## Repository
负责查询和持久化。

Repository 只表达 Query、Insert、Update、Delete、Lock 和 Pagination，不包含 Permission、Frontend 文案或跨 Domain 流程。

## Model
SQLAlchemy ORM。

## Schema
Pydantic 输入输出。

## 抽象
平台差异使用 Connector/Adapter。
禁止大量 `if platform == ...` 散落全项目。

## Core Domain V1 业务规则

- User、Shop、Device 的 API 通过各自 Service 调用 Repository。
- ShopDeviceBinding 由 ShopService 管理创建、启用和停用，只表达 Device 对 Shop 的执行资格。
- ShopDeviceBinding 是普通多对多关系；同一 Shop 可绑定多台 Device，不存在 PRIMARY/BACKUP 或唯一主设备。
- `Shop.enabled` 是店铺业务启用状态，不是自动化、RPA 或 Worker 开关。
- `DELETE /shops/{shop_id}` 的正式语义是软移除：同一事务写入 `deleted_at`、停用 Shop 并停用全部启用的 ShopDeviceBinding；Credential、ShopSession 和历史引用保留。
- 普通 Shop List、Detail、Picker 与业务 Service 默认排除已移除 Shop；按 ID 读取已移除 Shop 返回 `SHOP_NOT_FOUND`。只有明确的内部维护/审计代码可使用包含已移除记录的查询。
- Task 通过有序 `task_shops` 保存零到多个明确店铺执行上下文。创建时对整个集合统一校验并只创建一个 Task；不得把关系塞进 input 或按 Shop 自动拆 Task。Shop 软移除的 PENDING/RUNNING 保护与 Task Cancel 仍未建立，本阶段不得借账号下发顺手改变既有软移除语义。

## Access Foundation V1

- Team 与 TeamMembership 由 Access 模块的 Service / Repository 管理；API 不直接操作数据库。
- `role_code` 表示未来“能做什么”，`data_scope` 表示“能看哪些数据”，两者不得互相推导。
- ActorContext 是请求级小对象，不保存 ORM Entity、Request 或 Worker Principal。
- Active Team 必须由 Backend 验证有效 Membership。多 Active Team 且未指定上下文时必须失败，
  不得随机选择第一条。
- Data Scope 只允许 `self / team / all`。未知值必须 fail closed，绝不回退为 ALL。
- 单实体读取未来也应把 ID 条件与 Scope 条件放进同一个 SQL Query，避免先读取再在 Python
  中判断造成资源存在性泄漏。

## Device 生命周期

`Device.enabled=false` 只禁止设备承接新 Task，不撤销 Worker Token、不删除 Runtime/Inventory/历史 Task，也不伪造 OFFLINE。软移除才设置 `deleted_at`、停用启用中的 `ShopDeviceBinding` 并撤销当前 Worker Credentials。普通仓储查询默认排除软移除记录，历史关系使用显式 including-deleted 查询。

Device UUID 是永久历史身份；任何重新接入都创建新 UUID。

## Notification 模块

NotificationChannel 是系统级 Integration 配置，第一版支持 `feishu_webhook`、`wecom_webhook` 与设备离线/恢复两个事件开关。业务模块只调用 NotificationService，不感知 Provider payload。
