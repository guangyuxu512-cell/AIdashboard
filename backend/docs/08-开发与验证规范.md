## PostgreSQL Integration Test

真实数据库测试使用 `integration` marker，与默认单元测试保持可识别边界。默认 `pytest` 排除这组破坏性测试，必须显式执行 `pytest -m integration`。

- 唯一连接来源是 `BACKEND_DATABASE_URL`，不得为测试建立第二套连接配置。
- 未提供连接时，Integration Test 必须明确 Skip，不得使用 SQLite 替代或报告为通过。
- 包含 Alembic downgrade 的破坏性验证仅允许在专用 `control_center_dev` 数据库执行。
- 常规 Integration Fixture 只确保升级到 `head`，不再自动 `downgrade base` 清空已经用于人工验收的开发事实。新增 Migration 的降级闭环由当前任务显式执行 `head → previous → head`，并在前后核对需要保留的数据。
- Integration Test 数据使用可识别的 `stage-2a1` 前缀，并在测试结束后按稳定 ID 清理。
- 真实连接可用时，通过 `pytest -m integration` 单独运行数据库闭环验证。
