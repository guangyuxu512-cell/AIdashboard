# Electron 打包升级与验证

## Windows 正式发行包 V1

Windows V1 使用 Electron `44.3.0` 与 electron-builder `26.16.1` 生成 x64 NSIS per-user
one-click 安装 EXE。Fuse 工具要求 Node.js `>=22.12.0`；正式构建只能从干净且已提交的 Feature
工作树执行：

```powershell
cd electron
pnpm run package:win
```

构建脚本先运行 Electron build 与 unit tests，再生成安装包、`release-manifest.json` 和
`SHA256SUMS.txt`。产物位于受 Git 忽略的 `electron/release/`；Gate 1 完成后，把与候选提交
匹配的 EXE、manifest 和 checksum 复制到 `D:\中控台\dist\desktop\`，不得提交二进制、
unpacked 目录或构建日志。

Electron `win32-x64` artifact 的官方 SHA-256 固定在 builder 配置中。缓存命中和离线构建仍会
执行 checksum 校验；升级 Electron 时必须同时从对应官方 `SHASUMS256.txt` 更新该值，禁止关闭
校验或仅信任第三方镜像。

固定发行身份：

- Version：`1.0.4`（店铺登录同步及成功留窗；保留1.0.3主题、系统默认外缘与阴影修复）；
- App ID / NSIS upgrade identity：`com.siyu.controlcenter`；
- Product：`思余AI中控台`；
- Executable：`SiyuAIControlCenter.exe`；
- userData：`%APPDATA%\Siyu AI Control Center`；
- Production Console / Backend：`https://119.29.188.118/`。

安装包只包含编译后的 Main、Preload、IPC、Service、Contract 与 package metadata，并使用 ASAR。
Worker 不进入安装包，仍是独立长期进程；Renderer 不承载 Worker 循环。源提交 SHA 会进入安装
文件名、manifest 以及 ASAR 内的 package metadata，避免把无法对应审核代码的 EXE 交付。

## Production Renderer 与 HttpOnly Session

开发 Electron 只允许加载已登记的本机 `127.0.0.1:5173` 或 Integration `5180`。正式安装包忽略
最终用户环境变量，固定加载与 API 同站的 HTTPS Production Console。这样 Axios 的
`withCredentials=true` 可以使用 Backend 的 `Secure + HttpOnly + SameSite=lax + Path=/api/v1`
人员 Session；不得改回 `file://` 后放开 `Origin=null`、关闭 `webSecurity`，也不得把 Raw Session
Token 暴露给 Renderer。

主窗口只允许同 Origin 导航，拒绝跨 Origin redirect、`window.open` 和所有权限请求；Preload 只在
固定生产 Origin 与两个已登记开发 Origin 暴露既有 `window.desktop`。Main 再校验 IPC 必须来自主
Frame 和当前受信任 Origin。平台登录 BrowserWindow 使用独立 persistent partition，不加载
Preload，也不会得到桌面桥接。

## 打包安全

正式包保持 `contextIsolation=true`、`sandbox=true`、`nodeIntegration=false`、
`webSecurity=true`、`allowRunningInsecureContent=false`、`webviewTag=false`，并关闭 Production
DevTools。构建时启用以下 Electron Fuse：

- 禁用 `ELECTRON_RUN_AS_NODE`、`NODE_OPTIONS` 与 Node CLI inspect；
- 启用 Windows Cookie OS-level encryption；
- 启用 embedded ASAR integrity 并只允许从 ASAR 加载应用；
- 关闭旧 `file://` 额外权限。
- 显式启用 WASM trap handlers，并以 `strictlyRequireAllFuses=true` 阻止 Electron 升级时静默继承
  未知 Fuse。

Cookie encryption 是单向的发行契约，后续版本不得关闭，否则既有 Cookie store 会不可读。

## 安装、升级、卸载与回滚

1. 用户先核对发布记录中的 SHA-256，再双击安装 EXE；NSIS 在当前用户目录安装并创建桌面、开始
   菜单快捷方式，完成后启动应用。
2. 升级直接运行较新版本的同 App ID 安装器，不先卸载。固定 userData 路径不会随版本或安装目录
   变化，因此人员 Session、平台 persistent partition 和 `management-login-profiles.json` 保留。
3. Windows“已安装的应用”可正常卸载；`deleteAppDataOnUninstall=false`，卸载不会删除 userData。
4. 应用级回滚使用已留存且校验通过的上一版安装器。V1 不修改 Backend、数据库或 Migration，
   但回滚前仍应备份 userData；启用 Cookie encryption 后不得回滚到关闭该 Fuse 的构建。

V1 明确未配置 Authenticode 证书和自动更新服务。安装器与应用均为 unsigned，Windows 可能显示
SmartScreen 警告；升级依靠人工获取并运行新安装器。签名或自动更新必须另建 Feature、凭据与发布
渠道后接入，Handoff 不得把它们标成已启用。

## 验证

至少验证：

- `pnpm run typecheck`、`pnpm run test` 与 production NSIS x64 build；
- ASAR 包含 Main 与 Preload，Fuse 值符合本文件，安装 EXE 的 Product Version / architecture 正确；
- 实际双击安装、快捷方式启动、标准卸载登记、单实例和关闭重开；
- Production 登录、HttpOnly Cookie，以及关闭重开后的 Session 恢复；
- Preload / typed IPC、Light / Dark / System 标题栏主题；
- Topbar 拖动、双击最大化、最小化、最大化/恢复和关闭；
- 边缘缩放与菜单/抽屉/提示无裁切；窗口外缘使用系统默认行为，不再验收已取消的自定义圆角；
- 抖店与拼多多独立登录窗口均能打开并由用户关闭，主窗口继续可用；不得创建真实业务 Task；
- 安装 EXE、Version、源 SHA、size、SHA-256、签名状态、自动更新状态和验证时间已记录。

Gate 1 Handoff 必须列出候选 SHA、Green `dev` 基线、完整改动范围、测试与安装证据、
`Migration=none`、回滚方式、未覆盖项，以及交付 package path / SHA-256。

本轮清理修改 Main/Preload，必须交付匹配最终候选 SHA 的新桌面安装包。仅部署服务器前端不会更新已安装的 Main/Preload；升级仍用同 App ID 安装器覆盖，保留 userData。用户配色验收已通过，外壳圆角需求已取消；ca97 复验正常窗口、主题切换和主要操作后按 Gate/Release 流程发布，不重复要求用户确认配色。

Shop Login Session Sync V1 同样需要新版1.0.4 Main/Preload，不能只更新服务器前端。
先由 ca97 在唯一 Real Electron 验证真实登录、目标身份、自动保存、保留窗口/再次置前、关闭重开和取消失败保护；
安装/升级、平台真实登录与生产受控恢复未执行时在交接中明确待验，不用单元测试或浏览器桥接夹具代替。
保留旧安装包和各自 manifest/checksum，交付目录按版本及候选 SHA 分开，禁止覆盖旧回滚材料。
