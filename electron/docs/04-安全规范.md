# Electron 安全规范

必须：

- contextIsolation = true
- nodeIntegration = false
- preload 白名单 API
- 参数校验
- 路径校验
- IPC 最小权限
- 生产页面固定使用与 API 同站的 HTTPS Origin
- 限制主窗口导航、redirect、window.open 与权限请求
- Main 校验 IPC sender 的主 Frame 与精确 Origin
- 主窗口仅在当前 Main WebContents、主 Frame 和请求/当前 URL 均匹配受信任 Renderer Origin 时，允许
  `clipboard-sanitized-write`；`clipboard-read` 与其他所有权限请求继续拒绝
- Production 禁用 DevTools，并以 ASAR integrity / Electron Fuse 收紧运行时
- 平台登录独立 Session 拒绝权限请求，正式包的平台窗口同样禁用 DevTools

禁止：

- 任意 shell command IPC
- 任意路径写文件 IPC
- 把账号密码/Cookie 暴露给 Renderer
- 在 console 输出敏感凭证
- 通过 `Origin=null`、关闭 `webSecurity` 或跨域 Raw Token 绕过 HttpOnly Cookie
- 向平台登录窗口或任意远端页面注入 Desktop Preload

标题栏主题同步是窄范围白名单能力：Preload 只暴露 `light | dark` 参数，Main 再次校验参数，并且只更新事件来源对应窗口。不得把 `ipcRenderer`、BrowserWindow 方法或通用窗口控制暴露给 Renderer。

1.0.5允许固定用途的店铺登录诊断落盘，不等于开放正式调试。只观察主WebContents主Frame、
消息来源及当前URL均匹配固定受信任Origin的指定前缀JSON，最大2048字符；拒绝未知字段、
非法UUID/枚举/数字和子Frame、外部Origin伪造事件。Main重新构造记录后写固定userData文件，
单文件512KiB、只保留一份轮转、队列128项。格式仅含随机关联/尝试ID、阶段/事件、枚举错误码、
errno、HTTP状态、耗时和布尔状态；无人员身份、Cookie/Token、payload、URL、Header或原始异常。
Node文件mode在支持的平台使用0700/0600；Windows沿用当前用户userData目录权限，不宣称POSIX
mode建立了Windows专用ACL。记录失败不影响业务，日志不是授权依据。
诊断阅读工具仅读固定文件并再次白名单重建，不接受任意路径，不进入安装包、不新增Renderer
文件访问、DevTools/CDP、任意JS/Shell或注入能力；所有已有窗口安全开关与Fuse保持原值。

1.0.6首次加载观察只作用于本attempt平台WebContents：导航序号与固定pathClass、文档HTTP，
原adapter既有五个账号probe的索引映射/HTTP/耗时/requestFailed，以及identityPresent/captureReady/
pageContextAvailable布尔。相同probe状态仅首条或变化记录，不保留原始结果或身份；脚本错误每个
主Frame导航至多20项，只有固定错误枚举/计数和明确CORS错误布尔，不记录message/stack/URL。
普通fetch失败不推断CORS、登录过期或风控；导航序号不证明用户手动刷新，须关联实际操作时间。
无session.webRequest hook，不改headers/请求/导航、不新增平台请求；取消/完成/超时/窗口关闭
卸载观察。可选字段、监听卸载或记录器故障均不改变捕获/保存/释放行为。正文未知字段仍拒绝，
正式DevTools及任意调试能力保持关闭。
