# 日志与结果规范

每条日志至少可关联：
- task_id
- device_id
- skill_id
- shop_id（需要时）

禁止只返回“执行失败”。

错误应返回稳定 error_code。
最终错误码以正式 Contract 为准，不得自行新增同义错误。

日志必须脱敏：
- password
- cookie
- token
- authorization

截图、文件、报表等通过统一 Artifact 机制收集。

运行中日志统一通过 Runtime Event Bus 发出；Executor/Provider 不直接请求 Backend。
每个 Task 的 `seq` 从 1 递增，Backend 以 `(task_id, seq)` 幂等持久化。事件批量回传，
terminal 前立即 flush；短暂上传失败保留在有界内存缓冲并有限重试，不中断正在执行的
Provider。详细协议见 `08-运行状态与日志协议.md`。

Python Business Skill 只能通过内部 SDK 的 `SkillContext.log()` 和
`SkillContext.progress()` 产生 `log/progress` 事件。隔离子进程使用 Worker 内部事件桥把事件
交回父进程的同一个 Runtime Event Bus；Business Skill 不知道 Event API、批次、重试或 seq。
成功结果统一使用 `SkillResult(summary, data)`，JSON 序列化后上限 64 KiB，只承载摘要、计数和
少量结构化结果；业务明细应通过后续领域 API 持久化，大文件留给未来 Artifact/Resource 能力。
