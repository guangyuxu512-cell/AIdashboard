# AI生图模块现状与后端接入需求 V1

> 审计日期：2026-09-01
> 审计范围：`frontend/src/features/ai-workbench`、其页面与路由、通用资产实体、现有 Backend Assets 能力及相关测试。
> 审计约束：本文只记录代码已经表达的事实和由现有交互必然带出的能力需求；不定义最终 API、数据库字段、Job 模型、Provider 字段或权限模型。

## 1. 结论摘要

AI 生图模块当前是 **Frontend 页面壳 + Development-only Visual Mock** 阶段，不存在可执行的真实生图链路：

- `/ai-workbench/generate` 仅有禁用的素材、生成模式、输出类型、提示词/模板和“开始生成”控件；没有状态、提交事件、API Client、Query、Store 或结果数据。
- `/ai-workbench/assets` 与 `/ai-workbench/templates` 的正式路由均是禁用控件加 Empty State。只有开发环境且 URL 查询参数精确为 `?visualMock=1` 时，才加载本地 Fixture 和内存交互。
- 当前没有 AI Image API、AI Image Service、Provider Adapter、AI Job、AI 队列、AI 历史记录或 AI Provider 配置的 Backend 实现。
- 系统已有正式的通用 Assets API、Human 登录守卫及 Team Scoped Asset 基础能力；AI 工作台目前没有调用或接入它们。

因此，下一阶段的重点不是替换某一个 Mock 函数，而是先把 Visual Mock 中已经被用户操作的模板、商品素材分组与素材角色，和正式的生成任务/结果能力分别形成经确认的 Contract。当前代码还不足以确认模型、尺寸、质量、Provider、异步状态枚举、取消或重试语义。

## 2. Frontend 现状

### 2.1 路由与页面

| 页面 | Route | Page Component | 当前状态管理 / 数据读取 | Mock 与真实 API 状态 |
|---|---|---|---|---|
| AI生图 | `/ai-workbench/generate` | `pages/ai-workbench/AiGeneratePage.vue` | 无 `ref`、Pinia、TanStack Query 或 API 调用 | Prototype；所有操作控件 `disabled`，结果区固定显示“暂无生成结果” |
| 素材库 | `/ai-workbench/assets` | `pages/ai-workbench/AiAssetLibraryPage.vue` | 正式路由无数据读取；Visual Mock 使用组合式 `ref` / `computed` / `watch` | 正式路由为禁用工具栏和“暂无素材”；仅 Development + `?visualMock=1` 加载 `AiAssetLibraryVisualMock.vue` |
| 模板库 | `/ai-workbench/templates` | `pages/ai-workbench/AiTemplateLibraryPage.vue` | 正式路由无数据读取；Visual Mock 使用组合式 `ref` / `computed` / `watch` | 正式路由为禁用工具栏和“暂无模板”；仅 Development + `?visualMock=1` 加载 `AiTemplateLibraryVisualMock.vue` |

三个页面的导航定义在 `features/ai-workbench/model/routes.ts`，并由 `app/router/index.ts` 懒加载。共同外壳为 `AiModuleShell`；生成页使用 `AiWorkbenchLayout` 和 `AiWorkspaceEmptyState`，素材库/模板库使用 `AiManagementToolbar`、`AiManagementLayout` 与 Empty State。

### 2.2 Store、Query 与 API Client

- AI Workbench 目录内没有 Pinia Store。
- AI Workbench 目录内没有 TanStack Query、Axios、`fetch` 或 AI 专用 API Client 的调用。
- `AiGeneratePage.vue` 没有任何组件状态；模板/素材的可交互状态都局限在 Visual Mock composable 的内存 `ref`。
- AI Workbench 也没有直接导入通用 `entities/asset` 的 API、Query 或 Mutation。

### 2.3 App 级认证与模块元数据

- 三个 AI 路由均没有 `meta.public`。`main.ts` 安装的全局 `installAuthGuard` 会要求非公开路由具有有效 Human 会话和已选 Active Team。
- 这是一套应用级登录体验守卫，不是 AI 模块自己实现的 User、Role、Permission 或 Data Scope。
- Module Registry 中 `ai-workbench` 已注册为“AI工作台”，`permissionCode` 为 `null`。当前前端不存在 AI 专属权限码或权限判断。

## 3. 当前生图主流程

### 3.1 正式路由实际流程

```text
用户进入 /ai-workbench/generate
↓
看见“素材”“生成模式”“输出类型”“提示词 / 模板”四个区域
↓
素材选择、单选项、文本输入和“开始生成”全部处于 disabled
↓
没有 click handler、没有表单提交、没有状态更新、没有网络请求
↓
右侧固定渲染“暂无生成结果”
```

结论：生成页目前是 **Prototype 页面结构**，尚未形成可提交的生图请求，也不存在“结果从哪里来”的实现。

### 3.2 Development Visual Mock 的独立流程

素材库和模板库不是生成流程的上游实现；它们分别在独立页面、独立本地状态中演示管理交互。Visual Mock gate 的判断严格为：`import.meta.env.DEV === true` 且 `route.query.visualMock === '1'`。生产构建不会加载这些 Visual Mock 组件，`?visualMock=true` 也不会启用。

```text
开发环境访问 /ai-workbench/assets?visualMock=1 或 /ai-workbench/templates?visualMock=1
↓
加载本地 Fixture
↓
用户在组件内存中操作分组、模板、上传预览或选择状态
↓
刷新页面、离开页面或生产环境访问后，状态不保留且不进入生成页
```

没有 Mock Generation、Mock Delay、Fake Provider Call、Mock Job Status 或 Fake Success 的生图执行流程。

## 5. 参考图与素材现状

### 5.1 AI 模块自己的素材表达

素材 Visual Mock 的 `MaterialAssetReference` 使用以下前端字段：`assetId`、`name`、`mediaType`、`sourceType`、`role`、`previewUrl`，可选 `width`、`height`、`sizeBytes`、`generationMode`、`objectUrl`。

- 角色为 `PRODUCT_SOURCE`（商品素材）、`STYLE_REFERENCE`（复刻参考）、`AI_OUTPUT`（AI成品）。
- 来源类型为 `LOCAL_UPLOAD`、`MATERIAL_IMPORT`、`AI_GENERATION`。
- Fixture 的预览图是内嵌的 `data:image/svg+xml`；它们是绘制占位图，并非真实商品、远程 URL 或真实生成结果。
- 开发态本地上传仅接受 JPEG、PNG、WebP，并用 `URL.createObjectURL(file)` 创建浏览器内存预览；删除/销毁时会 `URL.revokeObjectURL`。上传不会请求服务器。
- 当前生成页没有素材选择器，也没有读取这些 `assetId`、`previewUrl` 或角色的代码。

### 5.2 已存在但尚未接入的正式通用 Assets 能力

通用资料库实体已有正式 `AssetReadDto`：`asset_id`、`media_type`、`original_filename`、`content_type`、`size_bytes`、`sha256`、`source_type`、`created_at`。其 Frontend Client 已实现：

- 上传：`POST /api/v1/assets`
- 分页查询：`GET /api/v1/assets`
- 内容读取：`GET /api/v1/assets/{asset_id}/content`
- 删除：`DELETE /api/v1/assets/{asset_id}`

Backend 对应 `backend/app/modules/assets/api.py`。资料库的内容通过带认证上下文的 Blob 请求读取，不对外返回公开 URL 或 `storage_key`。这是可供未来 AI Job 复用的通用资产底座，**不是当前 AI Workbench 已经使用的 API**。

要让禁用的“开始生成”和“暂无生成结果”变为真实功能，通常需要某种方式表达以下事实；但当前代码没有确定名称、字段、状态枚举或接口形状：

- 一次生成请求及其输入快照；

其中“模型、Provider、质量、分辨率、参数格式、状态枚举、错误码、结果保留策略”均为当前代码无法确认的未知项，不能据此文档直接落库或定接口。

## 11. 异步任务需求

当前代码 **没有** PENDING、RUNNING、SUCCESS、FAILED 或任何等价状态；没有轮询、订阅、刷新恢复、离页继续、历史回看、多图并发、取消或重试逻辑。

因此：

- 当前 Frontend 不能证明最终必须使用哪组生命周期枚举；
- 当前 Frontend 也不能证明必须提供 Cancel、Retry 或并发参数；
- 一旦正式实现“开始生成”和结果区，异步状态与刷新后的结果恢复将成为需要产品和 Backend 共同确认的 Contract，而非沿用 Mock 推断。

## 12. Storage 与结果复用边界

当前 AI 模块没有自己的正式 Storage 调用。Visual Mock 的素材预览有两种临时来源：Fixture 的 `data:image/svg+xml` 和浏览器对象 URL；二者都不具备跨刷新、跨会话或生产环境持久性。

当前 UI 已明确演示的素材侧能力是查看、删除、选择和模拟下载。生成结果的永久保存、正式下载、加入通用资料库、作为下一次参考图，均没有在生成页实现。

项目现有 `AssetService` 已为未来 AI Job 留出边界：可信 Backend 上游可在生成成功后带 Ownership 调用 `AssetService.create`，Reference Asset 可走既有 Scoped Lookup。这说明未来可以复用统一 Assets 基础设施；它不等于本次应创建第二套 Storage，也不等于 AI 已完成接入。

## 15. 后端接入能力清单（不定义最终 URL）

### 15.1 为现有模板/素材管理交互落地所需

若产品决定将现有 Visual Mock 交互转为正式功能，Backend 至少需要提供能表达以下能力的 Contract：

1. 模板组与模板的读取、创建、更新、删除、启用状态和排序保存。
2. 商品素材分组的读取、创建、改名、删除及启用状态保存。
3. 商品素材分组与模板组的两类独立关联：普通生图和风格复刻。
4. 商品素材分组与已存在资产的关联，以及商品素材/复刻参考/AI成品的角色表达。
5. 使用真实 Asset 标识进行上传后展示、内容读取和删除的协调方式。

通用 Assets API 已覆盖上传、列表、内容读取、删除，但尚未表达上述 AI 分组、角色或模板关联；是否扩展既有 Assets、增加 AI 业务关联，必须在后续 Contract 设计时确认。

### 15.2 为“开始生成”变为真实功能所需

当前页面尚无提交实现，因此下列能力是实现该产品表面所必需的 **待确认后端能力方向**，不是已经确定的 API 设计：

1. 接收一次经过确认的生成请求，并关联其模板/提示词/素材引用。
2. 返回可供页面识别和追踪的执行实体或等价结果。
3. 查询执行进度、终态、失败信息和生成结果。
4. 让结果能通过统一资产或经确认的内容读取机制展示。
5. 在需要历史页或刷新恢复时，提供任务/结果查询。

Cancel、Retry、多图并发、批量创建、Provider 参数透传、回调/WebSocket/轮询等，不是当前 Frontend 已经提出的硬性 Contract；应在生成页真实交互设计后单独确认。
