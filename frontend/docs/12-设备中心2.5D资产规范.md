# 设备中心 2.5D 资产规范

## 1. 正式路线

设备中心采用“高品质预渲染或绘制美术资产 + 固定透视 + 前后遮挡 + 2D 动画素材 + Vue/Electron 合成”。这是一套 2.5D 运行时，不是 CSS/SVG 插画，也不是浏览器实时 3D。

Device、Worker、分页、Query、Drawer 与 Backend Contract 不依赖素材文件名或动画格式。Backend / Worker 只提供真实设备数据和状态，不负责美术表现。

## 2. 前端职责

`features/device-office` 负责：

- 将真实设备分页投影到固定 9 个 `WorkstationSlot`。
- 把 `empty / onlineIdle / busy / offline / error` 映射为 Actor 与屏幕表现。
- 加载主题场景、Actor、屏幕和前景遮挡资产。
- 管理固定画布缩放、层级、标签与交互热区。
- 将工位、角色、屏幕和标签点击统一转发到既有 Device Drawer。

视觉状态不得反写 Backend，也不得把本地 Idle、Walk、Coffee 等行为冒充真实 Worker Task。

## 3. 固定画布与 WorkstationSlot

设计画布固定为：

```text
1440 × 810
```

运行时只允许在 Stage 容器边界计算一次等比 `scale()`。各层不得单独响应式缩放、维护第二套坐标或用百分比重新推导布局。

正式工位坐标位于：

```text
frontend/src/features/device-office/model/office-layout.ts
```

每个 `WorkstationSlot` 至少包含：

```text
slotId
actorAnchor
actorScale
screenRect
labelAnchor
hotspot
zIndex
```

Slot 是前端投影坐标，不是设备实体、数据库字段或 Backend Contract。

## 4. 固定分层

```text
DeviceOfficeStage
├── OfficeBackground
├── BackEnvironment
├── DeviceActor × N
├── MonitorScreen × 9
├── ForegroundOcclusion
├── DeviceLabels
└── InteractionHotspots
```

- `OfficeBackground`：主题主场景。
- `BackEnvironment`：位于人物之后的独立环境层。
- `DeviceActor`：由 `ActorAssetProvider` 按表现状态与 Accent 选择素材。
- `MonitorScreen`：只覆盖 Manifest 指定的屏幕区域。
- `ForegroundOcclusion`：桌沿、植物等需要压住人物的透明前景。
- `DeviceLabels`：普通 DOM 状态标签，不属于美术资产。
- `InteractionHotspots`：透明点击区，开发校准模式才允许显示轮廓。

## 6. Manifest 与 Provider Contract

正式契约位于：

```text
frontend/src/features/device-office/assets/device-office-assets.ts
```

`manifest.json` 必须显式声明：

- 资产状态和版本。
- 设计画布尺寸。
- Light / Dark 场景各层 URL。
- Actor 各表现状态 URL 与格式。
- 屏幕各状态 URL 与格式。
- 开发参考预览 URL。

Actor 必须通过通用 `ActorAssetProvider` 解析，业务组件只传入 `actorState`、`accentVariant` 和 `accessoryVariant`。未来替换 Mascot 或动画格式时，不得修改 Device / Worker / VisualState 逻辑。

支持的正式资产形态为：

- PNG / WebP 静态分层图。
- Sprite Sheet。
- 透明序列帧。
- 透明 WebM。
- 经 Electron 兼容性和释放行为验证后的 PAG。

不得用 CSS Filter 给角色换色。Accent 变化由独立美术变体、可替换图层或资产自身支持的参数实现。

## 7. 状态映射

```text
empty       → Actor null / empty screen
onlineIdle  → idle Actor / idle screen
busy        → work Actor / busy screen
offline     → sleep Actor / offline screen
error       → error Actor / error screen
```

`coffee / walk / celebrate` 只属于未来本地视觉行为。没有可靠 Current Task Contract 时，Real API 的 `online` 只能映射为 `onlineIdle`，不得伪造 `busy`。

## 8. 资产缺失规则

正式美术资产缺失时：

- Stage 必须显示 `ART ASSETS PENDING`。
- 不得用 CSS/SVG 临时绘制机器人、桌椅、电脑、植物或办公室背景。
- Dark 开发环境允许加载人工提供的整张参考图，并必须标记 `REFERENCE_PREVIEW`。
- Light 没有正式资产时显示 `Light office artwork pending`，不得对 Dark 参考图使用滤镜伪造 Light。
- Actor、屏幕或前景资产缺失时对应层渲染为空，不得退回程序化占位物。

Production 不得把 `REFERENCE_PREVIEW` 冒充正式完成效果。

## 9. 交互、主题与性能

- Light / Dark 共用 `WorkstationSlot`、标签和热区，只替换场景与 Actor 美术。
- 点击角色、屏幕、标签或热区统一打开既有 Device Detail Drawer。
- 每页最多 9 个 Actor；重复静态素材应复用浏览器缓存。
- 视频、序列帧和 PAG 必须在页面不可见或离开设备中心时暂停，并释放计时器、监听和播放器资源。
- 尊重 `prefers-reduced-motion`，禁用非必要循环动画。
- 场景不得产生嵌套滚动或页面横向溢出。

## 10. 禁止路线

以下内容不属于现行方案：

- CSS/SVG 拼装的机器人、桌椅、显示器或办公室背景。
- 浏览器实时 Three.js / Tres.js / WebGL 办公室。
- GLB Mascot、桌椅、显示器或 Office Props Runtime。
- GLTF Loader、Avatar Clip、CanvasTexture 屏幕。
- Blender 自动化作为前端运行链路。

历史实现只保留在 Git 历史中，不得重新作为 Device Office 的现行实现引用。
