# 设备中心 3D 资产规范

## 1. 边界

设备中心 3D 视觉资源属于 `features/device-office` 表现层。Device、Worker、分页、Query、Drawer 与 Backend Contract 不依赖模型节点、材质或动画名称。

参考视觉是固定经营类游戏式斜俯视科技办公室：每页 3×3 共 9 个工位，白色圆润原创 AI 小员工，黑色高光面罩与 Cyan 眼睛。不得模仿现有商业 IP，也不得以运行时 Sphere / Box 几何体冒充最终资产。

## 2. 必需 GLB

正式启用场景前，以下文件必须全部存在于 `frontend/public/assets/device-office/`：

```text
mascot.glb
desk.glb
chair.glb
monitor.glb
office-props.glb
```

用途：

- `mascot.glb`：统一基础 Avatar、Rig、附件节点和动画。
- `desk.glb`：可重复实例化的统一办公桌。
- `chair.glb`：可重复实例化的办公椅。
- `monitor.glb`：显示器与独立 Screen 节点，用于 CanvasTexture。
- `office-props.glb`：办公室外壳、咖啡台、少量绿植和设备总览屏。

资产必须明确原创或具有可用于本项目的授权；来源、作者、许可证和修改记录应随资产一并登记。

## 3. 节点与动画契约

权威机器可读清单位于：

```text
frontend/src/features/device-office/assets/office-asset-manifest.ts
```

关键节点：

```text
mascot: AvatarRoot, Accent, AccessoryHeadset, AccessoryScarf, AccessoryBadge
desk: DeskRoot
chair: ChairRoot
monitor: MonitorRoot, Screen
office-props: OfficeRoot, CoffeeBar, OverviewScreen
```

Avatar 必须提供精确命名 Clip：

```text
Idle
Walk
SitWork
Sleep
CoffeeIdle
```

全部模型统一使用米、Y-Up、中心合理的 Pivot 和一致朝向。角色强调色只作用于 `Accent`；白色机身、黑色面罩和 Cyan 眼睛由基础角色资产统一定义。附件节点可按稳定 `device_id` 派生的 Avatar Variant 显隐，不进入业务契约。

## 4. 状态映射

视觉状态继续只映射现有真实设备状态：

```text
empty       → 空工位，无 Avatar，屏幕待机
onlineIdle  → Idle / Walk / CoffeeIdle
busy        → SitWork，屏幕工作动画
offline     → Sleep，屏幕关闭
error       → Avatar 保留，屏幕轻量红色 Warning
```

业务状态优先于本地动画。Waypoints 只属于场景配置，不使用 NavMesh，也不得反写 Backend。

## 5. 主题与性能

Light / Dark 共享模型、布局和相机，仅通过独立 `officeSceneTheme` 切换环境材质与灯光。屏幕使用约 5～10 FPS CanvasTexture；WebGL DPR 最大 1.5，不启用 SSAO、SSR、DOF 或 Motion Blur。

重复桌椅应使用共享 Geometry / Material 或实例化策略。只有有限主光源启用动态阴影。页面不可见时暂停或降频，场景卸载时释放 Renderer、Material、Texture、AnimationMixer 和 Listener，3D 模块保持 Lazy Load。

## 6. 验收门槛

只有正式 GLB 全部通过节点、动画、授权和视觉评审后，才能输出 Dark / Light、空工位、Idle、Busy、Offline、Error 与 Drawer 的正式验收截图。

缺少任一正式资产时：

1. Loader 明确返回未就绪或契约错误。
2. 禁止回退到旧程序化几何体。
3. 禁止宣称达到参考图视觉层级。
4. 保留列表视图、分页、状态标签与 Device Drawer 业务能力。

## 7. 美术源文件与静态评审资产

可重复制作的 Blender 源文件、建模脚本和静态评审 GLB 统一位于：

```text
3d-source/device-office/mascot/
```

静态视觉评审文件使用 `mascot-vN-static.glb` 命名，只用于造型、材质、比例和坐标评审。它不得写入或覆盖 `frontend/public/assets/device-office/mascot.glb`，也不放宽正式运行时对 5 个 Avatar 动画 Clip 的要求。视觉验收通过后，后续 Rig / Animation 阶段仍从同一 `.blend` 源文件继续演进。
