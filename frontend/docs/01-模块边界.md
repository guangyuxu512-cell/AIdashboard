# 前端模块边界

推荐依赖方向：

```text
app
↓
pages
↓
features
↓
entities
↓
shared
```

禁止 shared 反向依赖 pages/features。

## Pages
只做页面组合和页面级协调。
禁止把请求、格式化、业务规则直接堆进巨大 Page 文件。

## Features
表达用户动作，例如：
- create-task
- bind-device
- refresh-session

## Entities
表达稳定业务对象，例如：
- ShopStatus
- DeviceStatus
- TaskStatus

跨 Shop、Product、Order、Data Center、Task 复用的平台展示定义归属 `entities/platform`。Shop Entity 只保留 Shop Contract、状态和 Shop 专属展示，不得再维护平台名称、图标或 Select Options。

## Shared
没有业务语义。

重复 2 次以上、跨页面复用、同一实体重复展示时必须优先抽离。

## Device Office 领域表现边界

`features/device-office` 负责设备 Visual State、9 工位投影、稳定 Avatar 变体、Office Palette、GLB 资产契约与 Three/Tres 场景组件；它只依赖 `entities/device` 的 View Model 和 shared/store 基础能力。`features/device-management` 继续负责真实设备详情、编辑、影刀 Discovery 与列表动作，`pages/devices` 只协调 Query 结果、视图切换、分页与 Drawer。Three Object 禁止依赖 API/Data Source，`shared` 也不得反向依赖 Device Office。

Avatar、桌椅、显示器和办公室陈设必须通过 `features/device-office/assets` 的正式 GLB Loader 接入。运行时程序化 `SphereGeometry` / `BoxGeometry` 不得承担最终角色或商业场景资产；替换模型不得要求修改 Device / Worker View Model。
