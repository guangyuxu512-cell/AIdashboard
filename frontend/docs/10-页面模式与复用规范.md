# 10-页面模式与复用规范

## 1. 目的

本规范解决：

- 每个页面重新排版。
- 相同功能页面结构不一致。
- 筛选区、操作栏、表格、详情页不断复制。
- 页面越做越大。
- 新页面看起来像另一个系统。

原则：

> 页面允许业务内容不同，但页面骨架和高频交互模式必须统一。

---

## 2. 标准页面骨架

普通列表型页面：

```text
AppShell
└── Page
    ├── PageHeader
    ├── Summary / KPI（可选）
    ├── FilterBar
    ├── TableToolbar
    ├── DataTable
    └── PaginationBar
```

例如：

- 店铺中心
- 设备中心
- 任务中心
- 日志审计
- 权限员工列表

都应优先使用此模式。

---

## 3. PageHeader

统一包含：

- title
- description（可选）
- actions（可选）

禁止：

- 页面自行重新实现标题区域。
- 页面标题上下留白随意变化。
- 标题区域塞入大量业务表单。

---

## 4. FilterBar

统一负责：

- 搜索
- Select
- DateRange
- Status
- Reset
- Query

FilterBar 必须统一：

- 控件高度
- 控件间距
- 换行策略
- Reset / Query 排列
- 响应式策略

页面只提供筛选项定义，不自行实现另一套 Filter Layout。

---

## 5. TableToolbar

统一负责：

左侧：

- 批量操作
- 当前选择数量
- 视图切换（需要时）

右侧：

- 新建
- 导入
- 导出
- 刷新
- 列设置

主操作位置必须跨页面保持一致。

---

## 6. 列表页

列表页应将逻辑拆成：

```text
Page
↓
useXxxQuery
↓
Filter Model
↓
Table Columns
↓
Feature Actions
```

禁止一个 `.vue` 文件同时包含：

- 500 行 table columns
- API
- Dialog
- Form
- Status map
- 数据格式化
- 权限判断

---

## 7. 详情模式

优先分两类：

### Detail Page

适合：

- 信息复杂。
- 可独立访问 URL。
- 有多个 Tab。

### Detail Drawer

适合：

- 从列表快速查看。
- 不需要离开当前上下文。

同一 Domain 应尽量固定一种主详情模式。

---

## 8. 编辑模式

### Dialog Form

适合小型编辑。

### Drawer Form

适合中大型配置。

### Full Page Form

适合大型流程配置、Workflow。

禁止同一类对象：

```text
A 页面 Dialog 编辑
B 页面 Drawer 编辑
C 页面内联编辑
```

无明确理由地混用。

---

## 9. KPI / Summary

KPI 必须复用统一 StatCard。

统一：

- icon area
- label
- value
- delta
- loading
- error

禁止每个 Dashboard 卡片自行创建一套视觉。

---

## 10. 状态页面

任何主要数据页面都必须考虑：

```text
Loading
Empty
Error
PermissionDenied
```

不得只实现 Happy Path。

---

## 11. 页面滚动

默认：

```text
Electron Window
↓
AppShell 固定
↓
Main Content 单一主滚动区域
```

禁止：

- Body 一个滚动。
- Main 一个滚动。
- Page 一个滚动。
- Table 外再套一个无必要滚动。

局部滚动只在确实需要固定局部区域时使用。

---

## 12. 页面高度

禁止通过大量：

```css
height: calc(100vh - 173px)
height: calc(100vh - 217px)
```

为不同页面分别猜高度。

应由 AppShell / Page Layout 提供统一高度约束。

---

## 13. 页面模式组件

建议逐步形成：

```text
shared/components/
├── AppShell
├── PageHeader
├── PageSection
├── FilterBar
├── TableToolbar
├── DataTable
├── PaginationBar
├── StatCard
├── DetailDrawer
├── FormDialog
└── FormDrawer
```

业务页面优先组合，不复制内部实现。

---

## 14. Domain 组件

业务语义组件不进入 shared。

例如：

```text
entities/shop/ui/ShopStatus
entities/shop/ui/ShopSelector

entities/device/ui/DeviceStatus
entities/device/ui/DeviceSelector

entities/task/ui/TaskStatus
```

它们可以基于 shared/ui 实现。

---

## 15. 新增页面前检查

必须检查：

- 是否已经存在相同页面模式。
- 是否有 PageHeader。
- 是否有 FilterBar。
- 是否有 DataTable。
- 是否有 StatusTag。
- 是否有 Entity Selector。
- 是否有类似 Feature。

优先组合现有模式，不从空白页面开始手写。

---

## 16. 一致性优先

若需求截图与现有 Design System 冲突：

1. 判断截图是否代表新的全局规则。
2. 如果只是单页视觉偏差，优先适配现有 Design System。
3. 如果确实需要全局调整，更新 Token / Pattern 后统一应用。
4. 禁止只修改一个页面造成新旧不一致。

---

## 17. 阶段 0B 页面模式组件索引

统一从 `@/shared/components` 导入：

| 类型          | 组件                                                                             |
| ------------- | -------------------------------------------------------------------------------- |
| 应用骨架      | `AppShell`                                                                       |
| 页面骨架      | `PageHeader`、`PageSection`                                                      |
| 列表模式      | `FilterBar`、`TableToolbar`、`DataTable`、`PaginationBar`                        |
| 状态模式      | `LoadingState`、`EmptyState`、`ErrorState`、`PermissionDeniedState`、`StatusTag` |
| 摘要模式      | `StatCard`                                                                       |
| 摘要布局      | `SummaryGrid`                                                                    |
| 筛选字段      | `FilterField`                                                                    |
| 详情/编辑模式 | `DetailDrawer`、`FormDialog`、`FormDrawer`                                       |

`AppShell` 固定 Sidebar 和 Topbar，只有主内容区滚动。`DataTable` 统一组合 Loading、Empty、Error 与基础 `AppTable`；业务页面不得再次实现同类状态分支。

## 18. AppShell V2 与桌面密度

AppShell V2 使用 228px Sidebar 和 54px Topbar。Sidebar 在 Light 主题使用浅色中性表面，Dark 主题使用深灰表面；Active Item 由轻背景、Primary 文字和 2px 左侧 Accent 组成，禁止整块高饱和主色。

Topbar 默认展示真实当前模块 Breadcrumb 和紧凑主题入口，不提前实现通知、用户等假功能。

开发环境可显示：

- `UI 基础设施` 导航。
- Fixture / Real API 数据源说明。
- Backend 尚未提供筛选参数等开发提示。

Production 必须从普通 Sidebar 隐藏 Playground 导航，并隐藏上述实现细节。这一规则只影响展示，不允许修改 Query、Mapper 或 API 数据流。

密度调整必须通过 Token 与页面模式组件统一生效：Page 不得为 KPI、Filter、Table 或 Empty State 设置自己的高度和间距。
