# 10-页面模式与复用规范

## 1. 目的

本规范解决：

- 每个页面重新排版。
- 相同功能页面结构不一致。
- 筛选区、操作栏、表格、详情页不断复制。
- 页面越做越大。
- 新页面看起来像另一个系统。

原则：

> 页面允许业务内容不同，但页面骨架和高频交互模式必须统一。

---

## 2. 标准页面骨架

普通列表管理页面默认使用 Compact Management Pattern：

```text
AppShell
└── Page
    ├── Tab / Platform Bar（可选）
    ├── FilterBar + Primary Action
    ├── DataTable
    └── PaginationBar
```

例如：

- 店铺中心
- 设备中心
- 任务中心
- 定时计划
- 日志审计
- 权限员工列表

都应优先使用此模式。复杂详情页、编辑器、Dashboard 与独立工作区可按业务需要使用 PageHeader、Summary 或 TableToolbar。

---

## 3. PageHeader

统一包含：

- title
- description（可选）
- actions（可选）

禁止：

- 页面自行重新实现标题区域。
- 页面标题上下留白随意变化。
- 标题区域塞入大量业务表单。

普通列表管理页默认不使用 PageHeader。页面上下文由 Sidebar、Breadcrumb、可选 Tab / Platform Bar 和 Table 内容共同表达；不得重复显示同名大标题和固定说明。

---

## 4. FilterBar

统一负责：

- 搜索
- Select
- DateRange
- Status
- Reset
- Query

FilterBar 必须统一：

- 控件高度
- 控件间距
- 换行策略
- Reset / Query 排列
- 响应式策略
- Primary Action 最右侧位置

页面只提供筛选项定义，不自行实现另一套 Filter Layout。

Compact Management Pattern 中 `FilterField` 默认省略顶部 Label，使用明确 Placeholder / Accessible Name。重置、查询与新增/添加主操作必须位于同一个 FilterBar；主操作使用 `primary-action` Slot，不另占 PageHeader 或独立行。

---

## 5. TableToolbar

统一负责：

左侧：

- 批量操作
- 当前选择数量
- 视图切换（需要时）

右侧：

- 新建
- 导入
- 导出
- 刷新
- 列设置

主操作位置必须跨页面保持一致。

---

## 6. 列表页

列表页应将逻辑拆成：

```text
Page
↓
useXxxQuery
↓
Filter Model
↓
Table Columns
↓
Feature Actions
```

禁止一个 `.vue` 文件同时包含：

- 500 行 table columns
- API
- Dialog
- Form
- Status map
- 数据格式化
- 权限判断

---

## 7. 详情模式

优先分两类：

### Detail Page

适合：

- 信息复杂。
- 可独立访问 URL。
- 有多个 Tab。

### Detail Drawer

适合：

- 从列表快速查看。
- 不需要离开当前上下文。

同一 Domain 应尽量固定一种主详情模式。

---

## 8. 编辑模式

### Dialog Form

适合小型编辑。

### Drawer Form

适合中大型配置。

### Full Page Form

适合大型流程配置、Workflow。

禁止同一类对象：

```text
A 页面 Dialog 编辑
B 页面 Drawer 编辑
C 页面内联编辑
```

无明确理由地混用。

---

## 9. KPI / Summary

KPI 必须复用统一 StatCard。

统一：

- icon area
- label
- value
- delta
- loading
- error

禁止每个 Dashboard 卡片自行创建一套视觉。

---

## 10. 状态页面

任何主要数据页面都必须考虑：

```text
Loading
Empty
Error
PermissionDenied
```

不得只实现 Happy Path。

---

## 11. 页面滚动

默认：

```text
Electron Window
↓
AppShell 固定
↓
Main Content 单一主滚动区域
```

禁止：

- Body 一个滚动。
- Main 一个滚动。
- Page 一个滚动。
- Table 外再套一个无必要滚动。

局部滚动只在确实需要固定局部区域时使用。

---

## 12. 页面高度

禁止通过大量：

```css
height: calc(100vh - 173px)
height: calc(100vh - 217px)
```

为不同页面分别猜高度。

应由 AppShell / Page Layout 提供统一高度约束。

---

## 13. 页面模式组件

建议逐步形成：

```text
shared/components/
├── AppShell
├── PageHeader
├── PageSection
├── FilterBar
├── TableToolbar
├── DataTable
├── PaginationBar
├── StatCard
├── DetailDrawer
├── FormDialog
└── FormDrawer
```

业务页面优先组合，不复制内部实现。

---

## 14. Domain 组件

业务语义组件不进入 shared。

例如：

```text
entities/shop/ui/ShopStatus
entities/shop/ui/ShopSelector
entities/shop/ui/ShopMultiSelector

entities/device/ui/DeviceStatus
entities/device/ui/DeviceSelector

entities/task/ui/TaskStatus
```

它们可以基于 shared/ui 实现。

---

## 15. 新增页面前检查

必须检查：

- 是否已经存在相同页面模式。
- 是否有 PageHeader。
- 是否有 FilterBar。
- 是否有 DataTable。
- 是否有 StatusTag。
- 是否有 Entity Selector。
- 是否有类似 Feature。

优先组合现有模式，不从空白页面开始手写。

---

## 16. 一致性优先

若需求截图与现有 Design System 冲突：

1. 判断截图是否代表新的全局规则。
2. 如果只是单页视觉偏差，优先适配现有 Design System。
3. 如果确实需要全局调整，更新 Token / Pattern 后统一应用。
4. 禁止只修改一个页面造成新旧不一致。

---

## 17. 阶段 0B 页面模式组件索引

统一从 `@/shared/components` 导入：

| 类型          | 组件                                                                             |
| ------------- | -------------------------------------------------------------------------------- |
| 应用骨架      | `AppShell`                                                                       |
| 上下文切换    | `ContextSwitchBar`                                                               |
| 页面骨架      | `PageHeader`、`PageSection`、`ManagementListSection`                             |
| 列表模式      | `FilterBar`、`TableToolbar`、`DataTable`、`PaginationBar`                        |
| 状态模式      | `LoadingState`、`EmptyState`、`ErrorState`、`PermissionDeniedState`、`StatusTag` |
| 摘要模式      | `StatCard`                                                                       |
| 摘要布局      | `SummaryGrid`                                                                    |
| 筛选字段      | `FilterField`                                                                    |
| 详情/编辑模式 | `DetailDrawer`、`FormDialog`、`FormDrawer`                                       |

`AppShell` 固定 Sidebar 和 Topbar，只有主内容区滚动。`DataTable` 统一组合 Loading、Empty、Error 与基础 `AppTable`；业务页面不得再次实现同类状态分支。

紧凑列表只能显式组合既有能力：`FilterBar density="compact"` + `ManagementListSection density="compact"`，内部继续放既有 `TableToolbar`／`DataTable`／`PaginationBar`（工具栏与分页可同样显式传 density）。业务列宽、固定列、筛选／排序、分页数据及动作仍由页面负责，共享层不猜业务字段。

详情／编辑／确认 Overlay 声明在以上密度边界之外，不能认为换 Teleport 目标就退出主题。商品信息列显式传 `ProductInfoCell density="compact"`，详情不传。候选池、采集任务与商品库列表可在各自批准范围显式消费紧凑组合；页面仍不得复制共享组件或修改其默认值。

`ContextSwitchBar` 只负责横向切换的通用视觉、Active、Disabled、点击与图标 Slot，不识别 Shop、Platform 或 AI 等业务语义。店铺平台切换与 AI 模块切换必须在各自 Feature 中组装业务 Items，并共同复用该 Primitive，禁止复制其 CSS。

模块或平台导航保留默认 `appearance="framed"`；嵌入 Header、Toolbar 或字段区的短选项使用 `appearance="bare"`，不得由 Feature 通过 Border、Background、Radius 覆盖实现无框外观。

System Settings Navigation V2 使用 Feature 内的薄 `SettingsLayout + SettingsSideNav`：前者只提供一个
设置主 Surface、内部左导航与右内容区，后者只复用现有 Route、Auth 状态和 Button。它们不声明动态
设置注册、权限规则或 API。用户与权限的成员/团队短切换使用 `ContextSwitchBar(appearance="bare")`
嵌入同一工具栏；设置页不得再叠加导航 Card、Tab Card、筛选 Card 与表格 Card。

AI 模型管理复用同一设置壳和 `TableToolbar / DataTable / FormDialog`。它只组合模型目录业务字段与
`access_admin` 状态，不新增模型管理专属 Primitive、Token、页面 Surface 或 Provider 管理壳。

## 18. AppShell V2 与桌面密度

AppShell V2 使用 228px Sidebar 和 54px Topbar。Sidebar 在 Light 主题使用浅色中性表面，Dark 主题使用深灰表面；Active Item 由轻背景、Primary 文字和 2px 左侧 Accent 组成，禁止整块高饱和主色。

Topbar 默认展示真实当前模块 Breadcrumb 和紧凑主题入口，不提前实现通知、用户等假功能。

开发模块导航默认隐藏；只有本地开发环境显式设置
`VITE_SHOW_DEVELOPMENT_MODULES=true` 时才显示 `UI 基础设施` 导航。开发环境仍可显示
不占业务布局的轻量 Dev Badge / Debug Area。

Fixture / Real API 来源、Backend 筛选能力和“尚未接入”等实现说明不得作为普通业务页面的固定标题、Section Description 或占位区域。Production 必须从普通 Sidebar 隐藏 Playground 导航，并隐藏全部开发实现细节。这一规则只影响展示，不允许修改 Query、Mapper 或 API 数据流。

密度调整必须通过 Token 与页面模式组件统一生效：Page 不得为 KPI、Filter、Table 或 Empty State 设置自己的高度和间距。

## 19. Compact Management Pattern

普通列表管理页面采用以下稳定结构：

```text
Tab / Platform Bar（可选）
↓
FilterBar（无顶部 Label）+ Primary Action
↓
DataTable + PaginationBar
↓
DetailDrawer（可选、按需覆盖）
```

- 默认不显示 PageHeader 标题/说明、Section 标题/说明和固定开发实现提示。
- Primary Action 与筛选操作同栏并位于最右侧；窄窗口允许 FilterBar 内部换行，但不得产生页面横向溢出。
- DataTable 直接作为主体，继续统一复用 Loading、Empty、Error 和 Pagination。
- PageHeader、PageSection Header 和 TableToolbar 不被删除；复杂详情、编辑器、独立工作区或确有额外工具语义时仍可使用。
- 后续新增普通列表管理页面必须优先采用该模式。

## 20. 店铺与设备中心紧凑模式

- 平台图标、名称和前端支持状态统一由 Platform Registry 提供，页面不得写平台判断或重复 Options。
- 平台不在 FilterBar 重复出现；店铺平台、启用状态、负责人和名称由 Backend 在授权范围内分页前筛选。
- 列表只展示真实店铺、ShopSession 登录状态、负责人、设备绑定、Shop 业务启用状态和备注；自动化语义尚未建立时不展示“开启”或自动化列。
- 详情 Drawer 默认关闭，使用 `drawer-sm`，关闭后不参与主页面宽度计算。
- 店铺 Drawer 的“账号与连接”消费正式 Credential 脱敏状态与 ShopSession 元数据；Cookie、Token 和 Session Payload 不进入 Renderer。
- 设备中心同步使用无 PageHeader、无独立统计卡、无 Section Header 的紧凑结构；统计摘要、搜索、刷新和添加设备位于同一工具栏。设备名称、位置和影刀账号使用正式 Backend 搜索参数并在分页前筛选。

## 21. 店铺中心最终管理模式

店铺中心 V4 在 Compact Management Pattern 内采用以下列结构：

```text
Selection / 店铺名称 / 平台 / 登录状态 / 负责人 / 执行设备 / 店铺状态 / 备注 / 操作
```

- `Shop.enabled` 只显示为正式“店铺状态”，并通过既有 PATCH Mutation 启停；它不等于自动化、RPA 或 Worker 开关。AutomationConfig 尚不存在时自动化列继续隐藏。
- 登录状态直接来自 Shop List 的真实 ShopSession 状态投影，统一映射为未登录、待验证、有效、已失效；列表不展示 Cookie、Token、Version 或 Profile。
- 执行设备摘要消费既有 `ShopDeviceBinding` 映射：单设备显示名称，多设备显示“设备名 +N”；Drawer 统一展示和管理普通执行设备，不存在主设备/备用设备。解绑更新 binding `enabled=false`。
- 表格使用 selection column 完成当前可见行全选和逐行选择。批量开启、批量关闭与批量移除均隐藏；当前只提供带确认 Dialog 的单店“移除”。
- 操作列提供查看、启停和移除。移除后正常列表消失、设备绑定停用，但 Credential、ShopSession 与历史记录保留。
- 详情 Drawer 固定为基本信息、账号与连接、执行设备、操作记录四个区域；账号与连接内使用正式“登录会话”卡片展示状态、最近验证、最近采集与 Version，并复用健康检查和 Management Profile 恢复链路。
- 平台栏可展示淘宝、视频号等前端导航项，但 `ShopPlatform` 与 Backend Contract 仍只包含正式支持的平台；不支持项只筛选当前已加载 View Model，不伪造查询参数。
- 店铺 Page 和列表 Section 通过 Flex Fill 链消费平台栏、筛选栏以下全部剩余工作区。多条、1 条、空态的 Section 外部高度和 Pagination Y 坐标一致；表格主体按可用空间滚动，行高不拉伸。
- Device Center 与 Shop Center 共用 `ManagementListSection + DataTable(viewport="fill", appearance="list") + PaginationBar`，0 条、1 条和多条数据保持相同列表卡片高度与 Pagination Y 坐标。

## 21A. 设备中心管理列表与详情模式

设备列表固定为：`Selection / 设备名称 / 在线状态 / 当前执行 / 影刀 / 影刀账号 / 当前账号云端应用 / 绑定店铺 / 最后心跳 / 启用 / 操作`。设备名称通过 `DeviceIdentity` 组合统一 Monitor 图标；表头、行高、Tag、操作按钮和选择态全部沿用店铺列表的 `appearance="list"`。

设备 Drawer 采用四层结构：

1. 运行概览：当前状态、当前执行、最后心跳、绑定店铺数量。
2. 执行能力：可扩展的 Capability Card 容器，影刀优先；后续可追加 Python、Browser、EXE 等 Provider。
3. 最近执行：通过 Task List Contract 只显示已有真实终态，无真实记录时使用统一 Empty State。
4. 更多信息：折叠并弱化设备 ID、位置、标签、备注和 Worker 版本。

设备列表操作固定为 `查看 / 能力 / 停用或启用 / 移除`；设备编辑仍保留在详情 Drawer
Footer。“能力”直接打开统一 Device Capability Drawer：上半区仅展示 Backend Capability 中
`classification=business` 的“业务 Skill”，下半区在影刀 Provider READY 时展示当前账号的云端
Application。Internal Skill 保留在完整查询结果中供运行条件判断，但不得出现在普通业务能力
列表或计数中。Skill 与 Application
不得混成同一列表。

影刀 Application 表固定使用 `应用名称 / App ID / 参数配置 / 操作`，由能力 Drawer 复用唯一
表格组件。App ID 支持复制，操作提供配置与运行；配置继续使用统一 Dialog 维护通用参数
Schema，运行创建正式 Task。Device Drawer 的“查看能力”打开同一个能力 Drawer，不保留第二套
Application 弹窗实现，也不得为每个 App 动态注册前端模块或创建第二套运行日志视图。

Device Capability 的 Skill 与 Application 查询必须区分首次 Loading、成功空列表、首次 Error
和已有缓存后的后台刷新 Error：成功空列表使用中性 Empty State；已有缓存时后台失败继续保留
内容，不以 Error State 覆盖主体。Application 运行入口按 Device、Skill、Provider、Application、
参数的顺序给出唯一禁用原因，并通过 Tooltip 解释；Frontend 提示不替代 Backend Task Guard。

当前执行只使用 `空闲 / 待执行 / 执行中`；运行时单元格固定为单行
`状态 Tag + execution_display_name + 详情`，长名称 ellipsis/Tooltip，行高不得随 Task 开始、
步骤变化或结束而改变。当前步骤和日志只能进入既有 `TaskRuntimeDrawer`。最近执行只使用
`成功 / 失败 / 丢失或中断`。CPU、内存、系统和 Worker 版本不得作为设备中心主展示。

设备管理 Query 必须区分 Initial Pending 与 Background Fetching：首次无缓存才显示 Loading；
已有数据时保留 previous data，辅助查询失败保留上一次成功值并局部降级。表格不得先清空再
回填，行键固定为 `device_id`，后台刷新不得造成整表重新挂载、滚动跳动或行高变化。

Device Drawer 增加“Worker 凭证”区域：只显示未签发/已签发/已撤销与真实签发时间。签发、
轮换和撤销使用统一确认/结果 Dialog；Token 明文仅签发或轮换当次显示一次并支持复制，关闭后
不可再次读取。Token 不进入 Device 主表，也不展示 Hash、尾号或虚构最后使用时间。

设备列表与 Drawer 的生命周期操作统一提供“停用/启用、移除”。移除必须使用确认弹层明确 Token 撤销、绑定停用、历史保留与 UUID 不复用；活动任务错误使用 Backend 稳定消息，不在前端伪造删除成功。

RUNNING 行与设备 Drawer 可打开复用的 `TaskRuntimeDrawer`。它的普通视图只突出执行对象、状态、
设备、时间、结构化进度、当前信息、Terminal 结果或安全失败原因；运行日志占据 Drawer 主要剩余
高度。Task ID、Skill ID、Provider 和各类 UUID 仅进入默认关闭的“更多信息”。日志区独立滚动，
默认跟随最新，用户向上滚动后暂停跟随并提供“回到最新”。Drawer 关闭或 Task 终态后停止自动
轮询，Task Center 必须复用该组件，不得创建第二套运行日志视图。

## 21B. 任务中心管理模式

任务中心位于 `自动化中心 → 任务中心`，使用
`FilterBar + ManagementListSection + DataTable(viewport="fill", appearance="list") + PaginationBar`。
列表固定为 `状态 / 执行对象 / 设备 / 进度 / 当前信息 / 开始时间 / 操作`，行键使用稳定
`task_id`。执行对象按 `execution_display_name → Skill display_name → skill_id` 降级；长名称、
当前信息和错误摘要必须单行 ellipsis/Tooltip，不得改变行高。

筛选栏在同一行提供状态、设备、创建日期和搜索。创建日期默认最近 7 个自然日，并支持今天、
昨天、最近 30 天、自定义和全部；查询和重置都回到第一页，重置恢复最近 7 天。自定义日期使用
日期选择组件，不允许页面手写另一套日期输入。

进度只消费 Runtime Event 的结构化 `current / total` metadata。Python Business Skill 的
`ctx.progress()` 可显示 `3 / 10` 与消息；影刀普通 tasklog 没有结构化进度时显示 `—`，不得
从日志文本猜测百分比。当前信息按 progress message、status message、safe log message 的
顺序选择，FAILED/LOST 优先显示安全错误摘要。

Task 列表使用 TanStack Vue Query 自动刷新。首次无缓存才显示 Loading/Error；已有数据时
background fetching/error 保留旧列表，禁止清空、Skeleton 闪烁、滚动复位或整表重新挂载。
详情唯一入口为 `TaskRuntimeDrawer`：首次只读取最新有界窗口，“加载更早”使用 `before_seq`，
RUNNING 继续 `after_seq` 增量轮询，Terminal 停止轮询，PENDING 正常显示空日志。Drawer 的
渲染数量必须有上限；历史较长时不得一次请求或渲染全部事件。Yingdao tasklog 与 Python
`ctx.log()/ctx.progress()` 最终都进入同一 `task_events` 链路，Frontend 不区分两套日志系统。

Task 与 Result/Error 永久保留，Runtime Event 可按服务端保留策略清理。Drawer 必须区分：
从未产生事件、事件完整、较早事件已清理且当前为空、较早事件已清理但仍有晚到/较新事件。
后两种显示中性保留提示，不得误报请求失败，也不得伪造已经被清理的日志。

Device Center 回答“谁能执行、谁在线、当前设备大概在做什么”；Task Center 回答“有哪些
任务、排到哪、运行到哪、最终结果和日志”。不得把完整 Task 管理继续堆入 Device Center，
也不得建立独立日志中心。

## 21C. 定时计划管理模式

定时计划位于 `自动化中心 → 定时计划`，使用既有 Compact Management Pattern。列表固定展示
`计划名称 / 执行对象 / 设备 / 触发规则 / 下次执行 / 最近执行 / 开启 / 操作`；最近执行直接复用
Task Status，不建立 Schedule 成功/失败颜色体系。列表使用 TanStack Vue Query 适度后台刷新；
已有数据时 background error 保留旧列表，不反复显示 Initial Loading。

新增/编辑 Dialog 开放“影刀应用 / 业务 Skill + 店铺账号 + 每天固定时间”。两类执行都先选择未停用 Device，并复用 `entities/shop` 的 `ShopMultiSelector` 选择该 Device 有效绑定的 Shop；创建时默认全选，至少保留一个；
影刀应用继续读取 Provider Inventory、复用 `AutomationApplicationConfig`，业务 Skill 则读取
Device Scope Business Skill Catalog 并以通用 `SchemaParameterFields` 渲染 Input Schema。
Internal Skill 不进入选择器；Schema unavailable/unsupported 的 Skill 不可配置。离线但启用的
Device 可以配置，停用 Device 不可选。Frontend 不计算 `next_run_at`。

时区数据库值始终是 IANA ID；UI 由共享 Timezone Registry 显示中文常用时区，并将浏览器当前
Timezone 在缺失时追加为可选项。搜索同时匹配中文和 IANA ID。Select Overlay 必须受 Viewport
约束、内部滚动并允许自动向上/向下放置，不得撑高 Dialog Body 或越出 1366×768 视口。

详情 Drawer 展示计划信息、参数、执行历史和高级 ID；历史 Task 唯一打开既有
`TaskRuntimeDrawer`。移除是软归档语义，已生成 Task 和日志继续由 Task Center 查询。不得建立
Schedule 日志页、Schedule Task 状态机、Cron 编辑器或 Internal Skill 选择器。

系统设置的通知配置属于独立配置工作区，允许 PageHeader。通道列表与编辑器只呈现真实 NotificationChannel；Webhook 只显示“已配置/未配置”，不得回显或缓存明文。
