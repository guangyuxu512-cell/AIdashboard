# 页面与路由规范

## 工程初始化路由

阶段 0B 提供 `/` Design System 验证路由，用于验证 Renderer、AppShell、基础组件和页面模式。阶段 1A、1B 分别引入 `/shops` 店铺中心和 `/devices` 设备中心路由；阶段 2B 起两页通过统一 Data Source 支持 Frontend Fixture 与 FastAPI Real API，不连接 Worker 或虚构实时运行数据。

阶段 2D-2 起普通列表管理页统一使用 Compact Management Pattern：`可选 Tab / Platform Bar → FilterBar + Primary Action → DataTable → PaginationBar`。这类页面默认不显示 PageHeader、Section 标题、固定说明或筛选字段顶部标签；Sidebar、Breadcrumb、业务切换栏和表格共同表达页面上下文。`/shops`、`/devices` 已采用该模式。

建议路由：

```text
/dashboard
/shops
/shops/:shopId
/devices
/devices/:deviceId
/tasks
/tasks/:taskId
/workflows
/data-center
/ai-analysis
/permissions
/audit
/settings
```

Page 负责：

- 路由参数
- 页面级 Query
- 页面区域编排
- Feature 组合

禁止：

- 直接写大段业务算法
- 直接创建 HTTP Client
- 复制公共布局

## 滚动

默认 AppShell 固定，主内容区域负责页面滚动。
只有确有需求时建立局部滚动。
禁止多个不必要的嵌套滚动条。

阶段 0B 的统一滚动链路为：

```text
Electron Window
↓
AppShell（固定 Sidebar / Topbar）
↓
app-shell__content（唯一主滚动区域）
↓
Page
```

## Header

PageHeader 保留用于复杂详情页、编辑器和独立工作区，并继续使用统一 Token。普通列表管理页默认不渲染 PageHeader，禁止为了重复 Sidebar / Breadcrumb 上下文而占用额外首屏高度。
