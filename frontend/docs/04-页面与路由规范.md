# 页面与路由规范

## 工程初始化路由

阶段 0B 提供 `/` Design System 验证路由，用于验证 Renderer、AppShell、基础组件和页面模式。阶段 1A、1B 分别引入 `/shops` 店铺中心和 `/devices` 设备中心路由；阶段 2B 起两页通过统一 Data Source 支持 Frontend Fixture 与 FastAPI Real API，不连接 Worker 或虚构实时运行数据。

阶段 2D-1 起 `/shops` 使用紧凑列表模式：`PageHeader → 平台切换 → FilterBar → DataTable → PaginationBar`。详情只通过默认关闭的右侧 Drawer 按需显示，关闭后不得占用主内容宽度；店铺页不展示无真实契约支撑的 KPI、订单或 GMV。

建议路由：

```text
/dashboard
/shops
/shops/:shopId
/devices
/devices/:deviceId
/tasks
/tasks/:taskId
/workflows
/data-center
/ai-analysis
/permissions
/audit
/settings
```

Page 负责：

- 路由参数
- 页面级 Query
- 页面区域编排
- Feature 组合

禁止：

- 直接写大段业务算法
- 直接创建 HTTP Client
- 复制公共布局

## 滚动

默认 AppShell 固定，主内容区域负责页面滚动。
只有确有需求时建立局部滚动。
禁止多个不必要的嵌套滚动条。

阶段 0B 的统一滚动链路为：

```text
Electron Window
↓
AppShell（固定 Sidebar / Topbar）
↓
app-shell__content（唯一主滚动区域）
↓
Page
```

## Header

页面标题区使用统一 Token，禁止标题区占用大量垂直空间。
