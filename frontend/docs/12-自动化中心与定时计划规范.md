# 自动化中心与定时计划规范

## 导航与职责

Module Registry 是唯一导航来源：

```text
自动化中心（无 Route）
├─ 设备中心 /devices
├─ 任务中心 /tasks
└─ 定时计划 /schedules
```

Device Center 回答设备是否可执行；Task Center 观察普通 Task 队列、结果和日志；Schedule Center 只管理“何时创建 Task”。不得创建 `/automation` 空首页、Sidebar 第二份 children 或独立 Schedule 日志中心。

## 前端分层

- `entities/schedule`：Schedule DTO、View Model、Mapper、Data Source 与 TanStack Query；
- `features/schedule-management`：筛选、创建/编辑、启停、归档、详情和 ScheduleRun 交互；
- `pages/schedules`：组合 FilterBar、ManagementListSection、DataTable、Pagination 和 Overlay；
- 影刀应用参数复用 `entities/automation-application`；Business Skill Catalog 位于
  `entities/business-skill`；两类执行共享通用 Schema 参数字段，运行历史复用 `TaskRuntimeDrawer`。

Schedule UI 不替代 Backend Guard。执行类型只开放“影刀应用”和“业务 Skill”，不开放 Internal
Skill。离线但启用的 Device 可保存计划；停用 Device 在选择器中禁用。Application 只来自所选
设备的真实 Provider Inventory；Business Skill 只来自所选设备的 Catalog，参数仅消费 Catalog
Schema，用户不手填或猜测 Skill ID。Schema 缺失/不支持时明确禁用，成功空列表显示正常空态。

创建与编辑计划必须通过 `entities/shop` 的 `ShopMultiSelector` 选择所选 Device 有效绑定的店铺。
Frontend 只提交有序 `shop_ids`，不读取 Credential 明文，也不把账号或店铺关系塞进参数 JSON；
创建时默认全选当前绑定，至少选择一个。编辑已有 Schedule 时保留其已保存集合，Device 后续新增
Binding 不得自动加入。Schedule 触发后由 Backend 将整个集合复制到一个普通 Task，Worker Claim
再取得临时 `accounts`。即时影刀 Application 运行使用同一选择规则和同一 Task Contract，选择
多个 Shop 仍只创建一个 Task。

## 时间与刷新

触发规则的 `HH:mm` 属于 Schedule IANA 时区，不能按浏览器时区二次换算；数据库保存 IANA ID，
UI 使用共享中文 Timezone Registry。常用列表覆盖中国大陆、香港、台湾、日本、韩国、新加坡、
美国四个主要时区、英国、中欧、悉尼和珀斯；浏览器当前 IANA Timezone 不在常用列表时动态追加。
下拉搜索中文与 IANA ID，Overlay 受 Viewport 最大高度约束并内部滚动。`next_run_at` 是 Backend
返回的绝对 Instant，并按 Schedule 时区显示；Frontend 不计算下一次运行。

列表使用适度 Background Refetch。首次无缓存才显示 Loading/Error；成功空列表显示“暂无定时计划”；已有缓存的后台刷新失败继续保留内容。页面保持单一主滚动、列表 Flex Fill 和固定底部分页，在 1366×768 不产生页面级横向溢出。
