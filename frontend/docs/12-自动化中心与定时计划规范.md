# 自动化中心与定时计划规范

## 导航与职责

Module Registry 是唯一导航来源：

```text
自动化中心（无 Route）
├─ 设备中心 /devices
├─ 任务中心 /tasks
├─ 定时计划 /schedules
└─ 参数配置 /parameter-presets
```

Device Center 回答设备是否可执行；Task Center 观察普通 Task 队列、结果和日志；Schedule Center 只管理“何时创建 Task”。不得创建 `/automation` 空首页、Sidebar 第二份 children 或独立 Schedule 日志中心。

## 前端分层

- `entities/schedule`：Schedule DTO、View Model、Mapper、Data Source 与 TanStack Query；
- `features/schedule-management`：筛选、创建/编辑、启停、归档、详情和 ScheduleRun 交互；
- `pages/schedules`：组合 FilterBar、ManagementListSection、DataTable、Pagination 和 Overlay；
- 影刀应用参数复用 `entities/automation-application`；Business Skill Catalog 位于
  `entities/business-skill`；两类执行共享通用 Schema 参数字段，运行历史复用 `TaskRuntimeDrawer`。

Schedule UI 不替代 Backend Guard。执行类型只开放“影刀应用”和“业务 Skill”，不开放 Internal
Skill。离线但启用的 Device 可保存计划；停用 Device 在选择器中禁用。Application 只来自所选
设备的真实 Provider Inventory；Business Skill 只来自所选设备的 Catalog，参数仅消费 Catalog
Schema，用户不手填或猜测 Skill ID。Schema 缺失/不支持时明确禁用，成功空列表显示正常空态。

创建与编辑计划通过 `entities/shop` 的 `ShopMultiSelector` 选择所选 Device 有效绑定的店铺。
Frontend 只提交有序 `shop_ids`，不读取 Credential 明文，也不把账号或店铺关系塞进参数 JSON；
创建时可默认全选当前绑定，但店铺上下文是可选的：用户明确清空后必须保持 `[]`，后续列表刷新或
新增 Binding 不得回填。编辑已有 Schedule 时保留其已保存集合。当前 Business Skill Catalog 没有
“需要店铺”的正式字段，Frontend 不得根据应用名、Skill ID 或 `business` 分类猜测并强制店铺。
Schedule 触发后由 Backend 将整个集合（包括空集合）复制到一个普通 Task，Worker Claim 对空集合
返回 `accounts=[]`。即时影刀 Application 运行使用同一 Task Contract；选择多个 Shop 仍只创建一个
Task，未选择 Shop 则创建无店铺上下文的 Task。

影刀 Application 的运行与计划表单可从同一 Team 已保存的参数预设选择公共参数和店铺覆盖。新建表单在应用
有输入字段时默认停留在“请选择参数配置”，不自动选择第一份预设，也不默认展开旧应用模板；用户可明确选择
预设，或明确选择“本次手动参数”。真正没有输入字段的应用可直接运行并提交空参数。旧无预设 Task/Schedule
编辑时仍明确进入手动参数模式，保持其已保存参数，不改写历史快照。预设不绑定
固定设备：保存和触发仍由 Backend 对当时目标 Device、选中 Shop 的启用状态、有效 Binding 与 Credential
做正式验证。Frontend 不以预设中已有的 `shop_id` 证明授权，不自行合并覆盖；预设变更只影响之后新建的
Task，不能改写已有 Task。

## 参数配置库

`/parameter-presets` 是自动化中心下的参数配置管理页，不创建独立导航来源。它只读取当前 ActorContext
Team 可见 Device 的 Yingdao Provider Inventory 聚合出的应用选项，并列出当前 Team 的参数预设；可选设备
只作为筛选上下文，服务端在分页前把应用与预设限制到该设备实际上报的 `app_id`，不会创建设备专属预设。
响应不返回
设备、账号或店铺额外事实。应用字段定义只为新预设提供初始模板；每份预设保存自己的字段 schema snapshot、
参数值和店铺覆盖，两者保存状态分开显示。没有字段定义时，页面复用既有字段编辑 Dialog 的表单能力，但“管理字段”
只修改当前预设草稿；返回编辑器时保留未保存名称、参数和店铺草稿。

`/parameter-presets` 是创建、编辑、复制和删除预设的唯一管理入口；设备中心影刀应用的“参数配置”快捷入口
携带当前稳定 `device_id` 和 `app_id` 跳转到同一路由，刷新、前进后退和重置均以 URL 为筛选事实；不能传显示名称、
猜测名称或自动匹配名称。同名应用用稳定 `app_id` 区分；无效或当前 Team 不可访问
的标识必须明确提示。运行和计划中的“管理配置”也跳转到
同一入口，保留仅本次手动参数而不改变模板或预设。主编辑器将“公共参数”和“店铺差异”同时
显示：公共参数区域只在自身容器内滚动；店铺差异一行一家店，单店修改打开独立子弹窗。子弹窗确定只回填主编辑器
草稿，只有主编辑器保存才写服务端；取消子弹窗不得改变已存在草稿。覆盖只持久化不同字段，恢复继承仅移除该店的
覆盖键，因此 `0`、`false` 和合法空字符串不是“未设置”。字段管理复用既有字段编辑 Dialog，但作用域是当前
预设；复制预设会复制字段 snapshot、公共值和店铺覆盖。应用模板和其他预设的字段变化不得改变当前预设的字段
目录、预览、店铺差异或后续 Task/Schedule 物化。运行和计划
使用同一选择器，展示适用店铺、差异数量和可展开的本次参数摘要；如需管理预设，
跳转此唯一管理入口，不在运行或计划弹窗复制编辑流程。本页不创建 Task、不启动影刀，也不在前端合并 Worker 下发
参数；Task 与 Schedule 继续调用既有 Backend 预设快照契约。配置列表采用 Compact Management Pattern：
`ManagementListSection + DataTable(viewport=fill, appearance=list) + PaginationBar`。筛选与每页条数回到第 1 页，
删除末页最后一项回到有效页；表格主体独立滚动，分页栏固定在列表卡片底部并显示总数。

## PC 列表自动搜索

需要提交筛选条件的文本搜索显式复用 `useAutoSearch`：输入停止约 300ms 后提交，中文输入法组词阶段不提交，
回车、清空、重置和 Select/Date 等离散筛选立即生效并取消待执行请求。页面卸载或 Team Actor 切换会使待执行搜索失效；TanStack
Query Key 必须包含已提交筛选，从而使旧条件的晚到响应不能覆盖当前列表。搜索错误必须保留 Error/Retry，不得显示成
“暂无数据”。普通参数值、提示词及表单输入不使用此行为。

服务端分页搜索入口包括店铺、设备、任务、定时计划、资料库、人员、审计日志和参数配置；权限与筛选均在分页和
`total` 计算前执行。完整数据已加载后本地搜索的入口包括 `ShopMultiSelector`、AI 素材库、AI 模板库、批量产品选择；
`AssetMultiSelector` 仍调用正式分页 API（V1 选择窗口最多读取 100 项）。Visual Mock 的素材、模板和生成记录仅供明确
Mock/Visual 场景验证，但复用相同的输入交互。应用参数编辑器内的字段查找属于草稿编辑，不触发业务查询。

## 时间、重复规则与发生日期筛选

触发规则的 `HH:mm` 属于 Schedule IANA 时区，不能按浏览器时区二次换算；数据库保存 IANA ID，
UI 使用共享中文 Timezone Registry。常用列表覆盖中国大陆、香港、台湾、日本、韩国、新加坡、
美国四个主要时区、英国、中欧、悉尼和珀斯；浏览器当前 IANA Timezone 不在常用列表时动态追加。
下拉搜索中文与 IANA ID，Overlay 受 Viewport 最大高度约束并内部滚动。`next_run_at` 是 Backend
返回的绝对 Instant，并按 Schedule 时区显示；Frontend 不计算下一次运行。

表单只提供正式 `一次 / 每日 / 每周` 三种规则：一次性显示本地日期，周规则显示 ISO 周一至周日的
多选；日规则不携带日期或 weekday。列表把规则显示为“某日 HH:mm / 每日 HH:mm / 每周一、三 HH:mm”，
但仍只展示 Backend 返回的 `next_run_at`，不本地推导下一次 occurrence。

列表日期筛选有“全部日期 / 今天 / 指定日期”。后两者把浏览器明确的 `YYYY-MM-DD` 和 IANA 时区
成对传给正式 API；页面不得先拉全量数据再本地筛选。日期筛选匹配该本地日已发生的 Run 或当前下一次
occurrence，所以停用计划若有该日 Run 也可在“全部状态”下显示。

列表使用适度 Background Refetch。首次无缓存才显示 Loading/Error；成功空列表显示“暂无定时计划”；已有缓存的后台刷新失败继续保留内容。页面保持单一主滚动、列表 Flex Fill 和固定底部分页，在 1366×768 不产生页面级横向溢出。
